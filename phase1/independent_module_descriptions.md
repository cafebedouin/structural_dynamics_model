# Phase 1: Independent Module Descriptions

Generated by reading the top 40–80 lines of each module before consulting any audit document.

## Prolog Modules (core, top-level)

### abductive_engine.pl
Read-only diagnostic layer that monitors outputs from all other subsystems (structural signatures, MaxEnt, FPN, Dirac orbits, drift detection, logical fingerprints) and synthesizes structured hypotheses explaining why anomalies occur. It does not run any of those subsystems itself — it probes their dynamic state to check what has already been run, then activates 15 trigger predicates (T1–T11, T13–T16) for available data. Exports `abductive_run/2`, `abductive_hypotheses/2-3`, `abductive_genuine/2`, `abductive_artifacts/2`. The three-file decomposition (engine/helpers/triggers) was created in Phase 6B to break a circular dependency.

### abductive_helpers.pl
Shared dynamic facts and helper predicates extracted from `abductive_engine.pl` to avoid circular imports. Declares `abd_hypothesis/3` and `abd_run_info/3` dynamic facts, override tables (`known_override_signature/1`, `override_target/2`), zone helpers (`fpn_zone/2`, `one_hop_zone/3`), confidence computation, and subsystem availability checks. Serves both the engine and the triggers.

### abductive_report.pl
Standalone report script that orchestrates all prerequisites (MaxEnt, optionally FPN, lifecycle drift), runs the abductive engine, and writes a structured markdown report with artifact census, genuine findings, and investigation queue. Entry point: `run_abductive_report/0`. Pattern follows `maxent_report.pl` exactly.

### abductive_triggers.pl
Contains all 15 trigger predicate definitions (T1–T11, T13–T16) extracted from the original `abductive_engine.pl`. Each trigger produces a `hypothesis/7` term when its firing conditions are met. Triggers depend on `abductive_helpers.pl` only (not the engine) to break the circular dependency. T6 and T7 use FPN + drift; T4 uses MaxEnt + Dirac + drift; T8 uses MaxEnt + fingerprint + signature.

### arakelov_height.pl
Diagnostic module computing "boundary complexity" for each constraint — how genuinely undecidable the classification is. Height = ε × (raw_uncertainty + conditional_pressure), maximized across the four canonical observer contexts. Requires `maxent_run/2` to have been called first. Identifies constraints where the engine cannot decide type even after signature override. Exports `arakelov_height/2`, `high_complexity_constraint/1`, `raw_confidence_margin/3`, `post_confidence_margin/3`.

### bifurcation_export.pl
Export utility that emits classification data in a stable line format (`CLASSIFY:<id>:<power>:<type>`) for diffing across parameter perturbations. Two modes: standard 4-context export and full 156-context product-site export. Used by Python sweeps for before/after comparison. No module declaration preamble — minimal scaffolding.

### boltzmann_compliance.pl
Tests whether a constraint's classification factorizes as expected for a natural law (Boltzmann independence across Power × Scope grid). `cross_index_coupling/2` classifies at 12 contexts (4 power × 3 scope) and measures coupling score. Also implements `boltzmann_invariant_mountain/2` (four-test composite), `scope_invariance_test/2`, `excess_extraction/2`, and a memoization cache (`cached_classification/3`) cleared between scenario runs. Used as input to signature detection (FNL, FCR), purity scoring, and Dirac classification.

### coercion_projection.pl
Computes coercion vectors and gradients over time for legacy interval-based data. `coercion_vector/4` fetches four measurements (accessibility_collapse, stakes_inflation, suppression, resistance) at a specific time. `coercion_gradient/4` computes the finite-difference gradient at time T_now by looking at the next time point in the interval. `system_gradient/3` aggregates per-level gradients into a single system-level gradient using influence weights. This module works against `measurement/5` temporal data, not `constraint_metric/3` static data.

### config.pl
Single source of truth for all `param/2` facts. Declares aggregation weights, influence weights, metric naming dispatch keys, power modifiers (π), sigmoid parameters, all classification thresholds (rope/snare/tangled_rope floors and ceilings for both chi and epsilon), cognitive displacement, and operational parameters. Multifile and dynamic to allow sensitivity sweeps to overlay perturbations.

### config_schema.pl
Declarative specification for every `param/2` fact in `config.pl`. Each entry is `param_spec(Name, Type, Constraint, Description)` where Type is number/integer/atom and Constraint is range(Lo,Hi)/positive/oneof(List)/any. Also declares cross-parameter relationship violations. Used by `config_validation.pl` for automated schema checking.

### config_validation.pl
Schema-driven validation that checks all `param/2` facts against `config_schema.pl` at startup (before corpus load) and again after corpus load. Collects all violations, reports them to stderr, and halts with exit code 1 on failure. Checks: missing params, unknown params, type mismatches, constraint violations, cross-param relationship violations.

### constraint_bridge.pl
Maps CE v2.0 constraint types to diagnostic intensities for the legacy interval-based analysis path. `constraint_status/3` dispatches by claim type (mountain/rope/snare/tangled_rope/scaffold/piton) and returns a semantic label plus intensity value. Also implements recommendation feasibility checking (`recommendation_feasibility/3`) and veto actor derivation (`derive_veto_actors/0`).

### constraint_data.pl
Two-predicate bridge module. `base_extractiveness/2` delegates to `narrative_ontology:constraint_metric(C, extractiveness, V)` via the config dispatch key. `suppression_score/2` similarly delegates to the suppression metric. Declared multifile so domain_priors can contribute additional clauses.

### constraint_indexing.pl
Core context-indexed classification module. Every Mountain/Rope/Snare judgment is relative to WHO (agent_power), WHEN (time_horizon), WHERE (exit_options), HOW (spatial_scope). `extractiveness_for_agent/3` computes χ = ε × f(d(P)) × σ(S) where f is sigmoid and d is derived directionality. Implements `sigmoid_f/2`, `canonical_d_for_power/2`, `derive_directionality/3`, and the formal observer restriction operator (`observer_accessible/3`, `feature_access/3`). Also exposes `time_horizon/1`, `exit_options/1`, `spatial_scope/1` index predicates and `positional_displacement/2` for cognitive displacement.

### constraint_instances.pl
Provides specific `constraint_classification/3` rules for named constraints (extending the constraint_indexing multifile predicate). Contains historical constraint instances (e.g., `catholic_church_1200`) with context-specific mountain/snare classifications and invocations of `effective_immutability_for_context/2`.

### corpus_loader.pl
Centralized loader for testset `.pl` files. Guards against redundant loading via `corpus_loaded/0` dynamic flag. Reads `corpus_path` from config, bulk-loads all `.pl` files, then calls `config_validation:validate_config_postcorpus`. All analysis modules should call `ensure_corpus_loaded/0` rather than implementing their own loading.

### covering_analysis.pl
Analyzes the 12-point index grid (4 powers × 3 scopes) for redundancy and coverage gaps. Phase 1 finds which grid cells always agree (`grid_signature/2`, `pairwise_agreement/3`, `minimum_discriminating_set/1`). Phase 2 detects classification transitions between grid points that the 12-cell grid misses (`classify_at_interpolated/4`, `missed_transitions/1`). Based on Erdős–Selfridge covering systems.

### data_repair.pl
Stage 1 of the validation pipeline. Imputation engine that fills missing `measurement/5` facts using domain-specific epistemic priors, and bridges v3.4 testset data (`constraint_classification/3` format) into the `narrative_ontology` format (`constraint_claim/2`, `constraint_metric/3`). Pure return-value API: `repair_interval/2` and `bridge_v34_data/2` return bridge_result lists rather than asserting directly. `persist_bridge_results/1` does the asserting separately.

### data_validation.pl
Stage 3 of the validation pipeline. Audits `constraint_metric/3` quality after all tests have run. Checks completeness (required metrics present), ranges (values in [0,1]), classification consistency (metrics match claimed type), edge cases, and domain coverage. Uses dynamic `validation_error/3` and `validation_warning/3` facts. Runs after test execution, not before.

### data_verification.pl
Stage 2 of the validation pipeline. Structural gate for `measurement/5` facts (temporal coercion vectors). Verifies 32-point vector completeness per interval, value ranges, intent logic consistency, and paired temporal measurements. Runs during test execution (called by `test_harness.pl`). Failures block the test pipeline. Checks a different data structure than Stage 3 (measurement/5 vs. constraint_metric/3).

### diagnostic_summary.pl
Synthesizes verdicts from 12 diagnostic subsystems (signature, Boltzmann, purity, Dirac, fingerprint_voids, drift, context_gap, H1, maxent, fpn, abductive, synthetic_divergence) into green/yellow/red traffic-light verdicts per constraint. Does not change any classification. Includes an `expected_conflict_pattern` catalog of known architectural artifacts and a `diagnostic_selftest/0`.

### dirac_classification.pl
Maps DR constraint types to Dirac first-class / second-class mechanics. Mountains and snares are second-class (genuine restrictions, no gauge freedom). Ropes and scaffolds are first-class (coordination choices with gauge freedom). Tangled_ropes are mixed with `separability_factor/2` derived from `reformability_score/3`. `gauge_orbit/2` collects all (type, context) pairs across standard contexts. `gauge_fixed/3` flags observers who cannot see the full constraint structure. `full_dirac_report/3` aggregates the full picture.

### domain_priors.pl
Epistemic prior library. Provides domain category profiles (physical_natural, formal_logic, extractive_market, etc.) and API predicates (`get_prior/3`, `is_known_domain/1`, `flag_novelty/1`, `expected_signature/2`, `should_be_natural_law/1`). Implements stub multifile clauses for `drl_core:base_extractiveness/2` etc. that always fail, deferring to later-loaded modules.

### domain_priors_expanded.pl
Auto-generated corpus-derived defaults for domain priors. Contains `category_corpus_profile/2`, `type_corpus_profile/2`, `subcategory_profile/2`, and inferential defaults (`default_extractiveness/2`, `default_suppression/2`, `default_resistance/2`) derived from analysis of 617 constraints.

### domain_registry.pl
Auto-generated registry of 3,325 `domain_category/2` facts mapping constraint IDs to their inferred categories (mountain/rope/snare/tangled_rope). Used by `domain_priors:is_known_domain/1` and related predicates.

### drift_events.pl
Event detection engine for temporal change in constraint properties. Nine individual detectors: `detect_metric_substitution/1` (theater_ratio rising = Goodhart drift), `detect_extraction_accumulation/1` (extractiveness increasing over time), `detect_coordination_loss/1` (coordination declining while extraction persists), `detect_function_obsolescence/1` (alternatives exist + low resistance + high theater), `detect_sunset_violation/1` (current year past declared sunset), `detect_extraction_dried_up/1` (zombie constraint), `detect_is_piton/1` (internalized piton), `detect_coupling_drift/1`, `detect_purity_drift/1`. Also exports `drift_event/3-4` structured API, `drift_velocity/3`, `drift_acceleration/3`, and `drift_severity/3`. Key helper predicates: `metric_at/4` (value at specific timestamp), `metric_delta/5` (earliest-to-latest change), `metric_trend/3` (increasing/decreasing/stable), `safe_metric/3`.

### drift_report.pl
Unified scan and report generation over drift events. `scan_constraint_drift/2` collects all drift events for a single constraint with severity. `scan_constraint_drift/3` adds context-indexed events. `scan_all_drift/1` corpus-wide scan. `generate_drift_report/0-1` writes human-readable output. Delegates to `drift_events`, `transition_paths`, `network_dynamics`, and `drl_composition:non_monotonic_trajectory/2`.

### drl_audit_core.pl
Quick-check audit module operating on pre-computed chi values. `effective_extraction/3` multiplies base extractiveness by `power_modifier/2` (note: uses legacy direct-multiplication path, not the sigmoid pipeline). `structural_signature/3` applies chi thresholds to classify as tangled_rope/snare/rope/mountain. Marked as deprecated path; TODO to migrate to sigmoid pipeline.

### drl_boltzmann_analysis.pl
Stages 5–7 of the modal logic pipeline: Boltzmann-aware reformability scoring, purity-aware reform recommendations, and purity-qualified action algebra. `reformability_score/3` combines separability, coupling, and excess extraction. `purity_reform_recommendation/2` targets constraints with score below threshold. `purity_qualified_action/3-4` gates actions by purity level. `purity_adjusted_energy/4` computes action energy with purity penalty.

### drl_composition.pl
Stages 1–2 of the modal logic pipeline: composition rules and transformation tracking. Stage 1 (`composite_type/3-4`) determines how pairs of constraints compose. Stage 2 implements temporal modal logic for constraint evolution: `constraint_history/2-3` collects type states at each measured time point, `dr_type_at/3` determines type at a specific time, `transformation_detected/5` detects type changes between time points, `transformation_type/6` labels the change (capture/obsolescence/calcification/discovery), `canonical_transformation/6` deduplicates, and `predict_transformation/3` forward-predicts from current trends. Also exports monotonicity helpers (`monotonic_increasing/1`, `monotonic_decreasing/1`, `non_monotonic_trajectory/2`).

### drl_core.pl
Primary classifier. `dr_type/3` (indexed) and `dr_type/2` (analytical default) are the main entry points. `classify_from_metrics/6` is the single canonical threshold predicate called by all other classification modules. `dr_action/3`, `dr_mismatch/4`, `dr_signature/2` extend the API. Integrates with `structural_signatures:integrate_signature_with_modal/3` for signature overrides. Re-exports key predicates from `constraint_indexing`. Exports `snare_reform_threshold/2`.

### drl_counterfactual.pl
Stage 3 of the modal logic pipeline: counterfactual reasoning about interventions. `simulate_cut/2-3` simulates removing a constraint from a specific observer context. `dependency_chain/4-5` traces cascade effects. `infer_structural_coupling/3` infers edges from `dr_gradient_at/3` correlation — requires measurement/5 temporal data. `assess_scaffold_need/2-3` evaluates whether a scaffold is needed. `counterfactual_world/3-4` constructs a post-intervention world state. `dr_gradient_at/3` is a temporal predicate that fetches gradient values from measurement data.

### drl_fpn.pl
Stage 8b: Fixed-point network iteration. Extends one-hop purity propagation to multi-hop convergence via Knaster–Tarski (monotone non-increasing sequence bounded below by 0). State stored in `fpn_ep/3`, `fpn_intrinsic/2`, `fpn_iteration_info/4`. `fpn_run/2-3` runs iteration to convergence. `states_equivalent/3` checks convergence condition.

### drl_lifecycle.pl
Facade module (`:- reexport`) over four split modules: `drift_events`, `transition_paths`, `network_dynamics`, `drift_report`. All original exports remain accessible via `drl_lifecycle:predicate/N`.

### drl_modal_logic.pl
Convenience facade (`:- reexport`) over five split modules: `drl_composition`, `drl_counterfactual`, `drl_boltzmann_analysis`, `drl_purity_network`, `drl_fpn`. Kept only for backward-compatible module-qualified calls.

### drl_purity_network.pl
Stage 8: One-hop purity propagation through constraint networks. `constraint_neighbors/2-3` discovers neighbors via three edge sources. `effective_purity/3-4` computes contamination-adjusted purity. `type_contamination_strength/2` and `type_immunity/2` parametrize contamination. `network_purity_metrics/2`, `cluster_purity/3`, `contamination_path/5`, `weakest_link_purity/3` provide network-level analytics. `network_qualified_action/3-4` gates actions by network context.

### fingerprint_report.pl
Standalone script that loads the corpus, runs logical fingerprint analysis on all constraints, and writes a markdown report with shift pattern families, void analysis, and cross-type fingerprint distribution. Entry point: `run_fingerprint_report/0`. Uses `:- initialization`.

### fpn_report.pl
Standalone script that runs the fixed-point network iterator on the corpus and outputs a markdown report comparing one-hop vs. multi-hop effective purity values. Entry point: `run_fpn_report/0`.

### gap_diagnostic.pl
Analyzes the institutional-to-moderate d-value gap (d=0.000→0.646) where the plurality of missed covering-analysis transitions occur. Partitions constraints into groups A/B/C based on behavior at the midpoint d=0.323. Uses `classify_at_interpolated/4` from `covering_analysis`. Dynamic facts accumulate intermediate results.

### genuine_findings_query.pl
Diagnostic query script that runs the full pipeline (MaxEnt, abductive engine) and profiles each genuine abductive finding in detail. Not a module — standalone script with `run_query/0` entry point.

### giant_component_analysis.pl
Investigates Erdős–Rényi phase transitions in the constraint network as coupling threshold varies (threshold sweep 0.10–0.90). Four phases: map current network, threshold sweep, contamination propagation through giant component, context comparison. Stores edges as `gc_edge/4` dynamic facts.

### global_delta_report.pl
Compares `derive_directionality/3` (v5.0 structural derivation) against `canonical_d_for_power/2` (legacy canonical fallback) corpus-wide across four standard contexts. Reports delta between derived and canonical directionality values.

### grothendieck_cohomology.pl
Computes Cech cohomological invariants of the DR presheaf. H⁰ = 1 if type is constant across all observer contexts (global section). H¹ = count of disagreeing observer-pairs (0..6, with 1 and 2 forbidden by site geometry). `cohomological_obstruction/3` is the core API. Also computes contextuality fraction CF = H¹/6. `corpus_cohomology/1` runs corpus-wide. Diagnostic only — does not modify classifications.

### inferred_coupling_protocol.pl
Verification script that tests whether `infer_structural_coupling/3` (from `drl_counterfactual`) can be activated by providing `measurement/5` temporal ground facts. Defines designed constraint pairs, verifies `dr_gradient_at/3` produces gradients, calls `infer_structural_coupling/3`, and measures network impact before/after.

### intent_engine.pl
Classifies intervals as `structural_coercive_intent` or non-intent based on four conditions: strong positive gradient, alternatives rejected, beneficiary asymmetry, and suppression above threshold. Delegates to `pattern_analysis` for gradient computation and `coercion_projection` for coercion math.

### invertibility_analysis.pl
Analytical overlay investigating whether classification transformations across observer positions are invertible. Tests "Strategy B" (type-only reconstruction) failure rates by orbit family. Uses `compute_chi_at_context/4`, `invert_chi_to_directionality/4`, `reconstruct_from_type_only/5`. Diagnostic only.

### isomorphism_engine.pl
Computes structural similarity between constraints based on a 7-point signature profile (`accessibility_collapse`, `stakes_inflation`, `resistance`, `beneficiary_count`, `viable_alternatives`, `temporal_stability`, `coordination_success`). `find_isomorphism/3` returns score ≥ `isomorphism_threshold`. `cluster_by_signature/2`, `generate_cross_domain_index/1`, `find_high_risk_isomorphism/3`.

### isomorphism_report.pl
Generates a markdown cross-domain isomorphism index table by scanning the knowledge base. Filters to show technical/formal vs. social/historical domain pairings. Uses `isomorphism_engine:generate_cross_domain_index/1`.

### json_report.pl
Main pipeline output generator. Loads corpus, queries all subsystems per constraint (classification, drift events, signatures, fingerprints, purity, MaxEnt, cohomology, abductive triggers, network), and writes `outputs/pipeline_output.json` with `per_constraint`, `diagnostic`, and `validation` sections.

### logical_fingerprint.pl
Extracts 7-dimension structural fingerprints from constraints: shift (perspectival classification pattern), properties (structural properties present), voids (absent-but-expected properties), actors (beneficiary/victim topology), drift (temporal trajectory), zone (metric region), coupling (Boltzmann compliance category). `known_constraint/1` discovers constraint IDs via `constraint_metric/3`. `shift_family/2` groups by shift pattern. Contains a local `metric_trend/3` implementation (duplicate of the one in `drift_events.pl`).

### maxent_classifier.pl
Maximum entropy shadow classifier that runs alongside the deterministic cascade. Computes probability distributions over types at each observer context, entropy scores, and disagreement flags. `maxent_run/2` is the main entry point. `maxent_disagreement/3` flags hard disagreements. Also implements `maxent_indexed_run/2` for quantum-complexity diagnostic (classical vs. context-indexed MaxEnt). All state stored in dynamic `maxent_dist/3` facts.

### maxent_diagnostic.pl
Deep-dive diagnostic script for MaxEnt analysis. Six tasks: missing constraints, per-type entropy, hard disagreements, non-overlapping distributions, Gaussian profiles, cross-diagnostic correlation. Standalone script.

### maxent_report.pl
Standalone script that runs MaxEnt classifier on the corpus and outputs a markdown report with entropy analysis, disagreement detection, threshold proximity, and cross-diagnostic correlation.

### measurement_layer.pl
Computes Wasserstein L1 (earth mover's) distance between MaxEnt probability distributions at adjacent observer positions along the power axis. `wasserstein_edge_transport/4` computes W1 for a specific pair. `wasserstein_transport_profile/2` all four adjacent pairs. `wasserstein_total_fracture/2` sums over all edges. `wasserstein_corpus_fracture/1` corpus aggregate. CDF construction uses the extraction chain (mountain < rope < tangled_rope < snare) as total order.

### narrative_ontology.pl
Core ontological schema. Declares multifile and dynamic predicates for: entities, intervals, events, constraint claims, human-readable labels, topic domains, recommendations, metrics (`constraint_metric/3`), temporal measurements (`measurement/5`), intent evidence (viable alternatives, rejected alternatives, beneficiaries, power changes), Boltzmann coupling profiles, and coordination vitality. The `measurement/5` predicate is the primary container for temporal data.

### network_dynamics.pl
Network drift detection: `detect_network_drift/3` finds constraints whose effective purity is declining due to contaminating neighbors. `network_drift_contagion/3` identifies which neighbors are contributing. `network_drift_velocity/4` derives rate from neighbor extractiveness drift. `cascade_prediction/3` computes threshold-crossing time predictions. `network_stability_assessment/2` provides network-wide classification.

### omega1_audit.pl
Audit module for constraints that return `unknown` at the analytical/global context. Computes full metric profiles, determines which gates block classification, performs cross-context analysis, and identifies gap regions (institutional/moderate transition zone). Stores results in six dynamic fact types.

### orbit_report.pl
Standalone script that computes `gauge_orbit/2` for every corpus constraint and writes both a markdown report and a JSON sidecar (`orbit_data.json`). Entry point: `run_orbit_report/0`.

### pattern_analysis.pl
Computes per-interval pattern classification for legacy interval-based data. `analyze_interval/4` (pure return API) and `analyze_interval/1` (legacy side-effecting API) compute system gradient, data completeness, and preliminary pattern (increasing_coercion/decreasing_coercion/stable) using `coercion_projection:system_gradient/3`.

### persistence_export.pl
Extended classification export with H1 and W1 topology data. Emits CLASSIFY, H1, and W1 lines per constraint for persistence barcode computation. Used by `python/persistence_sweep.py`.

### post_synthesis.pl
Detects T12: SYNTHESIS_DIAGNOSTIC_DIVERGENCE — cases where diagnostic verdict and abductive trigger set disagree. Case 1: red verdict with zero genuine triggers. Case 2: green verdict with multiple triggers. Canary trigger — zero output is the expected baseline.

### product_site_export.pl
Runs the full 156-context product-site cohomology computation and exports results to `outputs/product_site_orbits.json`. Used by `python/alt_power_transform_test.py`.

### psych_bridge.pl
Psychological alias bridge. Maps DR constraint types to psychological vocabulary: mountain → substrate, rope → negotiable_pattern, tangled_rope → hybrid_pattern, snare → self_extraction, scaffold → developmental_support, piton → abandoned_camp. Uses `with_psych_metric/2` to temporarily swap `internalization_depth` for `suppression_requirement`.

### purity_scoring.pl
Weighted composite of four Boltzmann structural tests: factorization (0.30), scope invariance (0.25), coupling cleanliness (0.25), excess extraction (0.20). Returns -1.0 for insufficient epistemic data. Used by drift detection, abductive triggers, FPN, and trajectory mining.

### quantum_verification_report.pl
Tests four predictions from the quantum complexity evaluation against the corpus. Reports results honestly — failed predictions are highlighted. Uses cohomology and MaxEnt.

### report_generator.pl
Primary report engine for interval-based analysis. `generate_full_report/1` is the main entry point — reads interval time bounds, classifies the interval, and generates DR detailed analysis output. Also generates omega resolution scenarios, omega triage, and gap patterns. Re-exports `type_metadata`. Contains a local override of `classify_interval/3`.

### scenario_manager.pl
Lifecycle controller. `clear_kb/0` retracts all dynamic facts from `narrative_ontology` and clears the Boltzmann classification cache. `load_and_run/2` loads a testset file and runs the test suite. `list_active_intervals/0` queries loaded intervals.

### scs_*.pl (scs_0anczbfz.pl, scs_16dnmltr.pl, etc.)
Auto-generated structural config sensitivity overlay scripts. Each file retracts one config param, asserts a perturbed value, loads the stack, and runs `product_site_export:run_product_export_to/1` to a named output file. Generated by `python/structural_config_sensitivity.py`.

### sheaf_analysis.pl
Implements `sheaf_status/2` (three-regime partition: genuine_sheaf / fragile_presheaf / manifest_presheaf) based on H¹ and Arakelov height. `block_consistency/2` checks that product-site orbits are internally constant within each power-level block. Diagnostic only.

### signature_config.pl
Declares threshold params for structural signature detection (natural_law_collapse_min, coordination_collapse_min, constructed_suppression_min, etc.) as `param/2` facts. These feed into `signature_detection.pl`.

### signature_detection.pl
Structural signature detection engine. `constraint_signature/2` classifies constraints into origin categories using a 7-feature profile cascade: FNL (false natural law) first, FCR (false CI rope), FSM (false summit mountain), then natural_law, coordination_scaffold, piton_signature, constructed_low/mid/high extraction, ambiguous. `integrate_signature_with_modal/3` applies origin-based overrides to metric-based classifications. `has_metric_perspectival_variance/1` checks variance across power contexts.

### signature_mapper.pl
Maps non-standard terminology to standard DR pillars based on `constraint_signature/2`. natural_law → mountain, coordination_scaffold → rope, piton_signature → piton, constructed_constraint → snare, ambiguous → rope.

### stack.pl
System initialization — loads all modules in dependency order. Five groups: (1) core schema (narrative_ontology, config), (2) data and priors (corpus_loader, domain_priors, constraint_instances), (3) core logic (constraint_indexing, boltzmann, signatures, purity, drl_core and all sub-modules), (4) management (scenario_manager), (5) functional engines and diagnostics.

### structural_signatures.pl
Backward-compatibility facade that re-exports `boltzmann_compliance`, `signature_detection`, and `purity_scoring`. Not the canonical import path.

### tangled_rope_examples.pl
Reference implementations of canonical tangled_rope examples (carbon_credit_trading_canonical, platform_network_monopoly_canonical, etc.) validated by corpus analysis. A data file providing baseline testset data for the tangled_rope category.

### test_harness.pl
Test execution harness. `load_scenario/1` loads a testset. `run_all_tests/0-2` runs the full DR audit suite for an interval: verification gate, data repair, constraint indexing checks, classification tests, mismatch detection, drift report. Invokes all three pipeline stages (data_verification, data_repair, then tests).

### trajectory_mining.pl
Extends the 24 orbit families (type-only) into richer structural families using continuous metrics, entropy, coupling, drift, and fingerprint voids. Four-phase architecture: trajectory computation per constraint, distance metric (4-component weighted), hierarchical agglomerative clustering, isomorphism detection. `structural_isomorphism/4` and `cross_domain_twins/3` are key outputs.

### trajectory_report.pl
Standalone script that runs trajectory mining and outputs a structured markdown report with family census, cross-domain isomorphisms, Phase A validation, and orbit refinement analysis.

### transition_paths.pl
Detects canonical degradation paths between constraint types. `transition_path/4` rules encode: rope→tangled_rope (extraction accumulating), tangled_rope→snare (coordination dying), rope→piton (direct obsolescence), scaffold→piton (sunset violation), scaffold→snare (calcification), scaffold→tangled_rope (extraction emerging), snare→piton (internalized), snare→false_mountain (naturalized). `degradation_chain/3` traces multi-step chains. `predicted_terminal_state/3` forward-predicts from current state. Uses `drift_events:metric_trend/3` to determine directionality.

### type_metadata.pl
Pure data predicates for constraint type descriptions, strategies, color codes, and severity ordering. No logic, no side effects. Extracted from `report_generator.pl` in Phase 6A.

### uke_dr_bridge.pl
Maps UKE feasibility + DR type combinations to UKE status codes (fantasy, blocked, viable, aspirational, investigate). `uke_status/3` routes through `determine_status/6`.

### utils.pl

## Python Scripts

### run_pipeline.py
Full pipeline orchestrator. Runs Prolog analyses (json_report, orbit_report, coverage, maxent, etc.) as subprocesses, then runs Python enrichment and reports. Structured error reporting with `StepResult`/`PipelineResult` dataclasses. Parallel execution via `ThreadPoolExecutor`.

### config_sensitivity_sweep.py
Perturbs each numeric `param/2` in `config.pl` by ±10% and ±25%, runs the validation suite for each perturbation via Prolog overlay, and rates each parameter as Critical/Moderate/Inert. Output: markdown table + `config_sensitivity_results.json`.

### directionality_sensitivity_sweep.py
Companion to config sweep. Perturbs hardcoded numeric constants in `constraint_indexing.pl` (`power_role_heuristic/4` and `exit_modulation/2`) that bypass `config.pl`. Uses abolish+assert overlay pattern. Output: `directionality_sensitivity_results.json`.

### cognitive_displacement_sweep.py
Measures classification boundary thickness by perturbing δ (cognitive displacement) at observer positions. Phase A: uniform sweep. Phase B: positional sweep (one position at a time). Generates Prolog overlays that set `positional_displacement/2` facts and run product-site export.

### enrich_pipeline_json.py
Produces `enriched_pipeline.json` from `pipeline_output.json` plus orbit, abductive, and game-theory JSON files. Computes derived per-constraint fields: confidence, rival_type, rival_prob, confidence_margin, confidence_entropy, confidence_band, coalition_type, tangled_psi, tangled_band, Nash distance, cover_story_type.

### linter.py
Prolog linter. Checks for common issues in constraint story `.pl` files: missing predicates, metric value ranges, claim consistency. Importable as library (`from linter import lint_file`). Has a `__main__` block for CLI use.

### shared/loader.py
Shared loading utilities. `load_json()`, `read_config()`, `load_all_data()`. Canonical implementations previously duplicated across ~14 scripts. Defines path constants for all output JSON files.

### shared/constants.py, shared/maxent.py, shared/schemas.py
Shared constants (including `shannon_entropy`, `compute_psi`, `classify_band`, `classify_coalition`), MaxEnt computation utilities, and schema validation for pipeline JSON files.

### classification_audit.py, corpus_profile.py, conflict_map.py, etc.
Thin wrappers that delegate to the `reports/registry.py` system. Each script was originally a standalone analysis; they now call `run_report(REPORTS["..."])` and print results.

### reports/registry.py, reports/queries/*.py
Report registry system mapping report names to query modules. Each query in `reports/queries/` implements the computation logic; the registry dispatches to them. Includes: classification_audit, conflict_map, corpus_profile, institutional_dissent, meta_reporter, omega_enricher, omega_reporter, pattern_mining, powerless_blind_diagnostic, red_spot_check, reform_threshold_report, sufficiency_test, type_reporter, variance_analysis.
