## Honest limitation I introduced (must not let the numbers stand as a clean verdict)
The arms were SEPARATE full gkc runs → each re-SCOPEd to a DIFFERENT reading-set, so every
comparison co-varies prompt/model WITH reading-set on small N (~35 drift-states/arm). The clean
design (SCOPE once → generate from the SAME manifests varying only prompt, then only GEN model) was
NOT run (I chose separate-runs to avoid a custom manifest-reuse driver). Differentiated read:
- **Direction-anchoring (example): reasonably supported** — reading-set noise wouldn't selectively
  deplete the example's own direction on its removal.
- **Husk-saturation as Haiku-prior: SUGGESTIVE but confounded** (model + reading-set + small N).

## Disposition (committer-axis existence proof)
