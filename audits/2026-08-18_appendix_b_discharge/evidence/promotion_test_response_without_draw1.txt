Note the ordering: `config:param/2` must already have the `testsets_flash` clause asserted *before* `corpus_loader:load_all_testsets` runs its `config:param(corpus_path, Dir)` lookup, since it's a plain lookup (not defaulted/overridable via retract), so asserting it first (before or right after loading `config.pl`, but definitely before triggering `ensure_corpus_loaded`) is what makes the override take effect — if `config.pl` also defines `param(corpus_path, 'testsets')` as a static fact loaded via `use_module`, you'd need `asserta` to make the new one clause tried by first-solution semantics, or better, retract the old one explicitly with `retractall(config:param(corpus_path, _))` before asserting the new value, to avoid relying on clause-order accidents.

To confirm it actually loaded `testsets_flash` rather than the default, I'd check the `[corpus] Loading N testset files...` line emitted on `user_error` — it's derived from `resolve_corpus_dir/2` applied to whatever `corpus_path` was in effect, so cross-check that count against `ls prolog/testsets_flash/*.pl | wc -l`, and additionally inspect a couple of `corpus_loader:corpus_constraint(Id)` values to make sure they correspond to basenames of files actually present in `testsets_flash/` and not `testsets/` (e.g. by diffing the two directories' file lists first if they might overlap in naming).
