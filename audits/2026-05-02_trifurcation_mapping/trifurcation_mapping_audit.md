# Trifurcation-to-Apparatus Mapping Audit

**Date:** 2026-05-02  
**Scope:** Does the DR apparatus retrospectively read as implementing the trifurcation
taxonomy from `docs/debugging_philosophy.md`?  
**Method:** Per-subsystem analysis grounded in Prolog module inspection, then aggregate
assessment.

---

## Executive Summary

**The mapping is partial — not clean, not independent.**

The apparatus implements all three trifurcation types, but asymmetrically:

- **Type C (indexical underspecification):** Two subsystems have clean, primary
  mappings. Gauge orbits and cohomology directly operationalize "what type is this?
  requires position specification."
- **Type B (structural inconsistency):** Five or more subsystems target Type B, with
  different detection layers (metric boundary, structural signature, network coupling,
  Boltzmann factorization). The apparatus is vastly richer here than the trifurcation's
  single "axiomatic inconsistency" category would predict.
- **Type A (frame drift):** One subsystem — drift analysis — has a clean Type A
  mapping. The trifurcation's richest category (five subcategories: vagueness drift,
  infinite subdivision, epistemic updates, identity criteria switching, decision
  framework oscillation) is represented by a single instrument.

Three or four subsystems are genuinely cross-cutting. Two or three extend beyond the
trifurcation into network-level phenomena it doesn't name. The trifurcation provides the
conceptual skeleton; the apparatus fills it in unevenly and adds structure the skeleton
doesn't anticipate.

**Strongest evidence for partial over clean:** Type A is thin. If the apparatus were
implementing the trifurcation's Type A as specified, there would be multiple dedicated
frame-drift detectors. There is one.

**Strongest evidence for partial over independent:** Every trifurcation type has at
least one clean implementation, and the correspondences are non-trivial. The apparatus's
rule cascade order (signature checks first, then threshold checks, then Mountain
credential last) parallels the trifurcation's diagnostic sequence (C → A → B) without
that parallelism being designed in.

## The Trifurcation Reference

From `docs/debugging_philosophy.md`:

**Type A (drift-generated):** Contradictions that require process to manifest.
Generated by shifting reference frames across stages while treating the frame as stable.
Fix: frame-fixing — freeze the reference criteria at t₀ and maintain them.

**Type B (structure-generated):** Contradictions that arise immediately from axioms or
rules, independent of process. Frame is already determinate. Fix: axiomatic revision.

**Type C (ambiguity-generated):** Contradictions that arise when a grammatically
singular question packages multiple distinct queries. Generated by failure to specify
indexical parameters (observer, time-slice, reference domain). Fix: index specification.

Diagnostic order: Stage 1 (index check, Type C) → Stage 2 (frame check, Type A) →
Stage 3 (structure check, Type B).

### Group 1: Type C — Indexical Underspecification Detection

#### Subsystem 1: Gauge Orbits

**Operational description:** Collects the complete set of (Type, Context) pairs for a
constraint across all standard observer positions.
`dirac_classification.pl:gauge_orbit/2` calls `site_contexts/1` and collects
`dr_type(C, Ctx, Type)` for each context. The orbit is non-singleton precisely when the
constraint's classification changes with observer position.
`grothendieck_cohomology.pl:orbit_vector/2` does the same thing in list form for
cohomology computation.

**Trifurcation mapping:** Type C — **clean.**

The gauge orbit directly answers "which constraints require position specification to
have a determinate type?" A non-singleton orbit is the apparatus's representation of
"the query 'what type is this?' is polymorphic — it resolves differently at different
observer positions." This is the operational content of indexical underspecification
applied to constraint classification.

Confirmed by `dirac_classification.pl:preserved_under_context_shift/2`: returns
`preserved(Type)` when orbit is singleton (index-invariant), `violated(Transitions)`
when not (index-sensitive). The naming — "preserved" vs. "violated" — encodes that
index-sensitivity is a failure mode.

#### Subsystem 2: Cohomology (H⁰/H¹ Measurement)

**Operational description:** Computes H⁰ (1 if all observer contexts agree, 0 if not)
and H¹ (count of disagreeing observer-pairs, range {0,3,4,5,6} on the 4-point site).
`grothendieck_cohomology.pl:cohomological_obstruction/3` calls `orbit_vector/2` and
`count_disagreeing_pairs/2`. H¹ = 0 means the constraint has a global section — its
type is position-invariant. H¹ > 0 measures the degree to which it does not.

The H¹ gap theorem (values 1 and 2 forbidden) is a structural consequence of the
4-observer site geometry. The contextuality fraction CF = H¹/6 measures the fraction of
observer-pairs that disagree.

**Trifurcation mapping:** Type C — **clean.**

H¹ is a quantitative measure of indexical underspecification. A constraint with H¹ = 0
has a type-claim that doesn't require position specification. A constraint with H¹ = 6
requires fully specifying which of four observer positions you're using, and even then
each position gives a different answer. Cohomology converts the presence/absence of
indexical underspecification (a binary) into a structured measurement of its degree.

The connection to Abramsky-Brandenburger contextuality
(`grothendieck_cohomology.pl:322–328`) places this squarely in the Type C tradition:
contextuality in the quantum-logic sense is exactly the failure to have a global section
— the failure of local (position-specific) data to compose into a position-independent
answer.

**Code citations:**
- `prolog/grothendieck_cohomology.pl:154–165` — `cohomological_obstruction/3`
- `prolog/grothendieck_cohomology.pl:171–179` — `count_disagreeing_pairs/2`
- `prolog/grothendieck_cohomology.pl:308–329` — contextuality fraction explanation

### Group 2: Type B — Structural Inconsistency Detection

Five or more subsystems detect structural inconsistency, each at a different detection
layer. This is the most densely operationalized part of the trifurcation in the
apparatus.

#### Subsystem 3: Boltzmann Compliance

**Operational description:** Tests whether a constraint's classification factorizes
across the Power × Scope grid. `boltzmann_compliance.pl:cross_index_coupling/2`
classifies the constraint at 12 (4 power × 3 scope) contexts and measures how many
scope-transitions flip the type at a given power level, then normalizes to a coupling
score in [0,1]. Boltzmann non-compliance = the constraint's behavior couples dimensions
that should be independent for a natural law.

The underlying theorem (`boltzmann_compliance.pl:48–54`): "The Boltzmann distribution is
the only distribution that correctly describes unrelated (uncoupled) systems." A Mountain
(natural law) must be uncoupled. Non-compliance means the Mountain claim is
axiomatically false.

**Trifurcation mapping:** Type B — **clean.**

Boltzmann compliance is a structural consistency test in the precise Type B sense: it
checks whether the constraint's behavior is consistent with what the structural axioms
require for its claimed type. A constraint that claims Mountain classification but fails
Boltzmann independence has an immediately derivable contradiction from the axioms (natural
laws don't couple dimensions) — no process, no observer-specification required to detect
the failure.

**Code citations:**
- `prolog/boltzmann_compliance.pl:88–97` — `boltzmann_compliant/2`

#### Subsystem 4: Purity Score

**Operational description:** A weighted composite of four Boltzmann structural tests
in [0,1]: factorization (0.30), scope invariance (0.25), coupling cleanliness (0.25),
excess extraction (0.20). `purity_scoring.pl:purity_score/2` combines these into a

Below 0.40 signals contamination; the score enables tracking structural degradation over

**Trifurcation mapping:** Type B — **clean (aggregate measure).**

Purity score is a continuous measurement of structural inconsistency. A low purity score
means the constraint's structural behavior contradicts the properties a well-formed
coordination mechanism should have — Boltzmann independence, scope invariance, absence
of excess extraction above the floor. This is Type B at a continuous scale rather than
a binary check.

The constraint's axioms, applied to its actual structure, produce a different type than

#### Subsystem 8: Structural Signatures (NL/Coordination/Constructed)

**Operational description:** `signature_detection.pl` classifies constraints into origin
categories based on a 7-feature profile: accessibility collapse, suppression requirement,
resistance, beneficiary count, viable alternatives, temporal stability, coordination
success. The cascade distinguishes natural_law, coordination_scaffold, piton_signature,
constructed_low_extraction, constructed_high_extraction, constructed_constraint, and
ambiguous. `structural_signatures.pl:integrate_signature_with_modal/3` applies the
origin-based override to the metric-based classification.

The three constructed sub-signatures use extraction thresholds to route to rope
(low-extraction), tangled_rope (mid), or snare (high-extraction) — preventing metric-based
snare assignments when the structural origin requires tangled_rope.

**Trifurcation mapping:** Type B — **clean, but layered.**

Structural signatures detect the inconsistency between a constraint's structural origin
and its metric-implied type. A constraint whose profile signals construction (active
enforcement + beneficiary asymmetry) but whose metrics would classify it as Mountain is
structurally inconsistent — the origin evidence contradicts the metric classification.
The sub-signatures extend this by also detecting internal structural inconsistency within
the constructed category (same origin, but different extraction levels imply different
types).

### Group 3: Type A — Frame Drift Detection

#### Subsystem 9: Drift Analysis

**Operational description:** `drift_events.pl` detects seven temporal change patterns
in constraint properties:
- `detect_metric_substitution/1`: theater_ratio rising above 0.5 (Goodhart drift —
  proxy becomes goal)
- `detect_extraction_accumulation/1`: base_extractiveness increasing over measurement
  intervals
- `detect_coordination_loss/1`: coordination_effectiveness declining while extraction
  persists
- `detect_function_obsolescence/1`: alternatives exist + low resistance + high theater
- `detect_sunset_violation/1`: current year past declared sunset year
- `detect_extraction_dried_up/1`: low extraction but high suppression persisting
  (zombie constraint)
- `detect_is_piton/1`: low extraction + high theater + no enforcement (internalized piton)
- `detect_coupling_drift/1`: Boltzmann coupling score increasing across measurements
- `detect_purity_drift/1`: purity score declining across measurements

Drift velocity (`drift_velocity/3`) and drift acceleration (`drift_acceleration/3`)
quantify the rate and second-order change.

**Trifurcation mapping:** Type A — **clean.**

Drift analysis is a direct operationalization of the "unmarked state mutation" that the
trifurcation identifies as the Type A mechanism. In debugging_philosophy.md's terms:
"The system assumes immutability while the state silently transforms." The apparatus
version: a constraint whose structural properties have changed (extraction accumulating,
coordination dissolving, theater rising) while the classification label remains unchanged.
The classification frame (the label) is being treated as stable while the state mutates.

Each drift detector corresponds to a specific Type A subcategory:
- `detect_metric_substitution`: Goodhart semantic drift (the predicate's extension shifts)
- `detect_extraction_accumulation`: temporal drift (the measured quantity changes)
- `detect_coordination_loss`: semantic drift in the coordination component
- `detect_sunset_violation`: temporal drift of the constraint's lifecycle boundary
- `detect_coupling_drift`: structural drift of Boltzmann properties

These are exactly the "unmarked state mutations" that produce Type A paradoxes in the
philosophical context.

**Note on thinness:** This is the only primary Type A subsystem in the apparatus. The
trifurcation's Type A was the richest category (Sorites, Zeno, Surprise Exam, Ship of
Theseus, Newcomb — five subcategories). The apparatus has one instrument for this
entire space. See Aggregate Analysis for interpretation.

**Code citations:**
- `prolog/drift_events.pl:100–178` — all seven drift detectors
- `prolog/drift_events.pl:181–220` — structured drift event API with evidence terms
- `prolog/drift_events.pl:270–370` — drift velocity, acceleration, severity

### Group 4: Boundary / Fragility Detection (Partial Type B)

These two subsystems don't detect manifest structural inconsistency — they detect
proximity to it. Parametric fragility is what Type B failure looks like before it's
triggered.

#### Subsystem 10: Arakelov Heights

**Operational description:** `arakelov_height.pl:arakelov_height_pair/3` computes
Height = ε × (raw_uncertainty + conditional_pressure), taking the max across the four
canonical observer contexts. raw_uncertainty = 1 − |raw_confidence_margin| measures
how close the pre-override MaxEnt distribution is to uniform. conditional_pressure =
|raw_margin − post_margin| measures how much the structural signature shifted the
classification from what the continuous metric evidence alone would produce.

Identifies constraints where the engine genuinely cannot decide: H¹=0 (no observer
disagreement) but the generative model was split before structural signatures resolved it.
These 238 constraints (from v6.11 §5) form the "uncertainty route" to institutional
boundary effects — distinct from the "dissent route" (H¹ > 0).

**Trifurcation mapping:** Partial Type B.

Arakelov height measures proximity to structural inconsistency — specifically, how much
the continuous metric evidence fails to unambiguously assign a type. It's not a Type B
detection in the full sense (no contradiction is yet manifest), but it predicts which
constraints are most vulnerable to Type B failures under small parameter changes. It
operates at the layer immediately preceding where Type B failures would become detectable.

Not Type C: the constraint does have a determinate classification (H¹=0, consensus
exists); the fragility is about that consensus being structurally precarious, not about
position-dependence.

Not Type A: no temporal process is involved; this is a static metric.

**Code citations:**
- `prolog/arakelov_height.pl:100–111` — `arakelov_height_pair/3` with Height formula
- `prolog/arakelov_height.pl:70–90` — `signature_pressure/3` (conditional vs.
  unconditional overrides)
- `deferential_realism_paper_v6.11.md §5` — 238-constraint "uncertainty route"

#### Subsystem 11: Fisher Curvature (ε-Sensitivity)

**Operational description:** `python/epsilon_sensitivity.py` computes Fisher information
I(ε) = Σ_types (1/P)(dP/dε)² using finite differences on the pre-override MaxEnt
distribution. Applied to the Arakelov "uncertainty route" constraints (H¹=0, high height,
Nash distance = 0). Identifies whether constraints on the consensus manifold are on a
steep MaxEnt ridge (high curvature, fragile consensus — 83% snare) or in a flat region
(low curvature, robust consensus — 70% snare + 28% tangled_rope, signature-anchored).

Fisher curvature is uncorrelated with confidence margin (r = 0.064) — confirmed
non-redundant with existing diagnostics.

**Trifurcation mapping:** Partial Type B — same logic as Arakelov heights.

Fisher curvature refines the Arakelov height diagnostic for the consensus manifold.
Both measure proximity to Type B failures at the continuous level. Neither detects a
manifest structural inconsistency; both identify constraints where small structural
changes would trigger one.

Fisher curvature is a Python-only diagnostic — not a Prolog subsystem.

**Code citations:**

### Group 5: Cross-Cutting Subsystems

#### Subsystem 12: Dirac Orbits

**Operational description:** `dirac_classification.pl` provides three distinct functions:

1. `dirac_class/3`: maps DR types to Dirac first-class (coordination choice = gauge
   freedom) vs. second-class (genuine restriction = no gauge freedom). Mountains and
   snares are second-class. Ropes and scaffolds are first-class. Tangled_ropes are
   mixed(separability), where separability is derived from `reformability_score/3`
   combining separability_factor, coupling_factor, and excess_extraction_factor.

2. `gauge_fixed/3`: returns true when an observer's local context sees mountain or
   snare AND another context sees a different type. Flags "from this position, what
   appears as immutable reality may be a coordination choice from another position."

3. `full_dirac_report/3`: aggregates orbit, class, freedom, consistency, and
   gauge_fixed status.

**Trifurcation mapping:** Cross-cutting B + C.

`dirac_class` (first/second-class decomposition, separability) targets Type B: it
characterizes the structural properties of the constraint — whether its components can
be factored (separability), whether it has genuine gauge freedom or frozen degeneracy.
This is a structural property analysis independent of any process.

`gauge_fixed/3` targets Type C: it detects that an observer is in a position-fixed
frame where they cannot see the full constraint structure. "You are in a gauge-fixed
frame — your classification may not reflect the full constraint structure" is the
operational version of "you haven't specified which observer position your query is
evaluating from."

The combined module is cleanly split along this line: the structural decomposition
(first/second-class) is Type B; the positional-frame detection (gauge_fixed) is Type C.

- `prolog/dirac_classification.pl:204–215` — `gauge_fixed/3`

#### Subsystem 13: MaxEnt Shadow + Wasserstein W₁

**Operational description:** `maxent_classifier.pl` runs a probabilistic shadow
classifier alongside the deterministic cascade, computing MaxEnt probability
distributions over types at each observer context. `measurement_layer.pl` computes
Wasserstein W₁ transport between adjacent observers' distributions — the L¹ distance
between CDFs.

Key output: `maxent_disagreement/3` flags "hard disagreements" where the deterministic
pipeline and the MaxEnt distribution assign different top types. W₁ measures continuous
distributional shift independently of discrete type-threshold crossings.

From v6.11: "A constraint can have H¹=6 with W₁ < 0.01 (maximal discrete obstruction
with minimal distributional shift) or H¹=0 with W₁ ≈ 1.0 (distribution shifts
substantially while type label stays constant)."

**Trifurcation mapping:** Cross-cutting C + partial B.

W₁ measures the continuous analog of indexical underspecification — how far the
underlying distributions shift across observer positions even when discrete type
assignments are stable. This is Type C at the distributional level: the extent to which
observer position matters for the full probability mass, not just the top classification.

MaxEnt hard disagreements (deterministic says X, probabilistic says Y) are partial Type
B: the deterministic cascade is applying structural signature overrides to produce a
classification that contradicts what the metric evidence alone would yield. This is a
structural inconsistency between metric evidence and classification output — detectable
statically, not process-dependent.

The two measures are deliberately designed as complements that "catch what the other
misses" (v6.11 §5.4), which is coherent with their different trifurcation targets.

**Code citations:**
- `prolog/maxent_classifier.pl:26–53` — module exports including `maxent_disagreement/3`
- `prolog/arakelov_height.pl:46–53` — `raw_confidence_margin/3` using MaxEnt
- `deferential_realism_paper_v6.11.md §5.4` — H¹–W₁ complementarity analysis

#### Subsystem 14: Mandatrophy Gap

**Operational description:** `report_generator.pl:format_mandatrophy_gap/3` computes
delta_chi = |chi(powerless) − chi(institutional)| and classifies severity (critical >
1.0, high > 0.5, moderate otherwise). Reports the magnitude of the extraction gap
between the most-affected and least-affected standard observer positions.

Mandatrophy itself (`narrative_ontology.pl:94–99`, `attribute(C, lifecycle, mandatrophy)`)
marks a terminal structural state: immutable + extractive + no exit. The `detect_omega/2`
predicate in `narrative_ontology.pl:305–312` fires when a constraint has extraction
(ε > 0.70) and hasn't been declared resolved.

**Trifurcation mapping:** Partial C, partial B.

The gap measurement (delta_chi) is Type C: it quantifies how different the answer to
"what type is this?" is depending on which observer position you're at. Large delta_chi
= high indexical underspecification in the practical sense (the contrast between what
powerless and institutional observers experience is massive).

Mandatrophy declaration is Type B: a constraint declared mandatrophy has a structural
property (immutability + high extraction + no exit) that is immediately inconsistent
with any response strategy other than containment. There's no process required to detect
this — the structural properties derive the terminal state directly from the axioms.

The gap diagnostic and the mandatrophy state are thus different failure modes with
different trifurcation targets, sharing a report section because they're both triggered
by high extractiveness.

#### Subsystem 15: Evaluative Convergence

**Operational description:** `python/evaluative_convergence.py` groups constraints by
shared beneficiary (from scenario_convergence.json) and network adjacency (explicit
edges in contamination_network) and detects four cross-constraint patterns:

- `convergent_signature`: ≥2 constraints in group share the same structural signature
- `convergent_institutional`: ≥2 constraints share the same institutional type while
  analytical disagrees
- `convergent_drift`: ≥2 constraints share the same critical-severity drift type
- `cover_story_topology`: one constraint with clean metrics (ε ≤ 0.25, intrinsic purity
  ≥ 0.80) has extractive neighbors (snare/tangled_rope, purity < 0.40) with a
  propagation_delta ≤ −0.15

**Trifurcation mapping:** Cross-cutting A + B, partially outside.

`convergent_drift`: Type A — detects the group-level version of frame drift: multiple
constraints are in simultaneous temporal transition, and the whole group's classifications
are temporally unstable. This is the drift subsystem applied across multiple constraints.

`convergent_institutional` + `cover_story_topology`: Type B — both detect structural
inconsistency at the group level. Convergent_institutional catches the pattern where the
institutional observer's classification contradicts the analytical observer's across a
group of structurally related constraints — a coordinated cover story rather than an
individual one. Cover_story_topology detects that a constraint's apparent structural
cleanliness is not an intrinsic property but a network position artifact.

`convergent_signature`: **Outside the trifurcation.** This detects that multiple
constraints in a group share a structural origin type — coordinated operation rather
than independent constraint formation. The trifurcation operates on individual reasoning
episodes about single entities. Convergent signature detection has no analog in the
trifurcation's vocabulary because the trifurcation doesn't distinguish "independently
constructed" from "coordinated set." This is a genuine extension.

### Group 6: Outside / Extending the Trifurcation

#### Subsystem 16: Network Purity Propagation

**Operational description:** `drl_purity_network.pl:effective_purity/4` computes
contamination-adjusted purity for a constraint by propagating purity degradation from
neighboring snares and tangled_ropes, with directional asymmetry (contamination flows
but not uplift), per-edge caps, and type-specific immunity (mountains immune, snares
and tangled_ropes contaminate). `drl_fpn.pl:fpn_run/2` extends this to multi-hop
fixed-point iteration, converging via Knaster-Tarski (monotone decrease on compact
lattice).

**Trifurcation mapping:** **Outside.**

The trifurcation operates on reasoning episodes about individual entities. Network
contamination propagation detects structural degradation of a constraint caused by
its coupling to other constraints — a multi-entity, systemic phenomenon. The three
trifurcation failure modes (frame drift, axiomatic inconsistency, indexical
underspecification) are all properties of individual analytical acts or individual
constraint structures.

A rope whose effective_purity has degraded due to contamination from neighboring snares
has not drifted (no temporal process), has no internal axiomatic inconsistency, and is
not indexically underspecified. The failure is structural coupling — which the
trifurcation doesn't name.

The closest trifurcation analog might be Type B (the constraint's actual structural
soundness contradicts its intrinsic purity score), but this is a stretch: Type B is
about logical contradiction from axioms, not about extrinsic contamination. Network
contamination is genuinely outside the trifurcation's taxonomy.

**Code citations:**
- `prolog/drl_purity_network.pl:39–58` — contamination propagation design rationale
- `prolog/drl_fpn.pl:36–59` — FPN convergence guarantees and Scott-continuity proof

### Coverage Check

**Type C (indexical underspecification):** Adequately covered. Gauge orbits + cohomology
provide both qualitative (orbit non-singleton) and quantitative (H¹ value) detection.
The Wasserstein W₁ supplement adds a continuous-measurement dimension. The two core

**Type B (structural inconsistency):** Heavily covered — the most elaborated part of
the apparatus. Five clean Type B subsystems operate at different detection layers:
Boltzmann factorization (independence test), FCR (coupling + extraction), FSM
(beneficiary structure), FNL (origin vs. behavior), Structural Signatures (origin
taxonomy). The multiplicity reflects genuine need: structural inconsistency at different
layers requires different detection instruments.

**Type A (frame drift):** Thinly covered — one clean subsystem (drift_events.pl).
This is the most significant coverage gap relative to the trifurcation's emphasis.
The trifurcation treated Type A as its richest category (five subcategories), but the
apparatus has only one primary Type A instrument.

**Explanation for Type A thinness (not a paper-draft proposal, a factual observation):**
The trifurcation was developed for philosophical reasoning episodes — individual acts
of analysis where the analyst's frame drifts over minutes or hours. The apparatus
analyzes structural properties of social constraints, with temporal evidence embedded
in constraint measurement histories (narrative_ontology:measurement/5 facts with
timestamps). Type A in the apparatus requires temporal data in the testsets. The majority
of testsets contain point-in-time structural data, not longitudinal measurement series.
Where temporal data exists, drift_events.pl detects it. Where it doesn't, there's
nothing for a Type A detector to work with. The coverage gap is partly a data
availability constraint, not purely an architectural omission.

### Patterns

**Pattern 1: Type B detection is multi-layered by design.**
The five Type B subsystems don't redundantly detect the same failure. They operate at
distinct detection layers that are partially independent:
- Boltzmann compliance: factorization across the Power × Scope grid
- FCR: cross-perspectival coupling + extraction at the Boltzmann layer
- FSM: beneficiary structure inconsistency with Mountain claim
- FNL: origin inconsistency (claims natural, fails Boltzmann)
- Structural Signatures: origin taxonomy (constructed vs. natural vs. coordination)

These five instruments are logically distinct — a constraint can fail some and pass
others. This multi-layer architecture is itself a structural finding: Type B inconsistency
in a power-stratified classification system requires redundant detection because the
same failure can manifest at metric, structural, network, and origin layers.

**Pattern 2: The cover-story mechanism is the apparatus's unique extension.**
The "cover story" detection (FCR + FSM + convergent_institutional + cover_story_topology)
is not a single trifurcation type — it's a two-level detection problem. At the chi level
(the routing layer), the structural inconsistency is visible: chi signals extraction. At
the type surface, the FCR mechanism or naturalization has resolved the chi signal into
apparent coordination. The trifurcation doesn't have a category for "structurally
inconsistent in a way that is systematically concealed."

From v5 §2.2: "Epistemic opacity produces parametric stability. Parametric fragility
(near-boundary, visible disagreement) and epistemic opacity (far-from-boundary,
disagreement concealed) are not merely distinct properties — they are inversely related."

The apparatus needs both Type B detection (structural inconsistency) AND its inverse
(the cover story mechanism that makes structural inconsistency parametrically stable).
The trifurcation has Type B; it doesn't have "Type B concealed by structural mechanism."

**Pattern 3: The three-type diagnostic order in the apparatus parallels the trifurcation.**
The apparatus's rule cascade applies signature checks (which catch structural
inconsistency = Type B) before threshold checks, and Mountain credential is earned last
by surviving all stress tests. This parallels the trifurcation's diagnostic sequence
(Stage 1: index check = Type C → Stage 2: frame check = Type A → Stage 3: structure
check = Type B), though in a different order: the apparatus inverts Stage 1 and Stage 3
for operational efficiency.

### Gaps

**Gaps in apparatus coverage of the trifurcation:**

1. *Type A is represented by one instrument.* The trifurcation's five Type A subcategories
   (vagueness drift, infinite subdivision, epistemic updates, identity criteria switching,
   decision framework oscillation) have only one operational analog (drift_events.pl).
   Epistemic drift (the analyst's knowledge state changing) is not operationalized at all.

2. *The trifurcation's Type C doesn't distinguish the two fragility modes.* The apparatus
   found that parametric fragility (Arakelov height) and epistemic opacity (FCR/FSM) are
   *inversely* related — a finding the trifurcation's Type C has no vocabulary for. Type C
   says "specify the index to resolve." The apparatus shows that some constraints have
   apparent specification (H¹=0) that conceals latent disagreement. The trifurcation
   doesn't distinguish genuine global sections from cover-story-stabilized ones.

**Gaps in trifurcation coverage of the apparatus:**

1. *Network contamination.* The apparatus detects structural degradation through coupling
   to other constraints. This is not a failure of any single constraint's frame, axioms, or
   index — it's systemic. The trifurcation has no vocabulary for this.

2. *Multi-constraint coordination.* Evaluative convergence's `convergent_signature`
   pattern detects that a group of constraints is operating as a coordinated set. This
   is outside both individual reasoning failures (A, B) and individual query
   underspecification (C).

3. *Two-level measurement (chi vs. type surface).* The apparatus detects failures at the
   flow layer (chi values) and at the classification surface (type labels) independently,
   and the gap between them is structurally informative. The trifurcation operates at a
   single layer — it doesn't have a theory of how failures at one layer can be concealed
   by mechanism at another.

## Assessment

**Which of the three possible answers best describes the situation?**

**Partial mapping** is the correct characterization.

The apparatus is not independent of the trifurcation. Every trifurcation type has clean
operational representation: gauge orbits + cohomology for Type C; drift analysis for
Type A; FCR/FSM/FNL/Boltzmann for Type B. The correspondences are non-trivial —
they name the same failure modes under different vocabulary and at different levels of
abstraction. "Indexical underspecification" in the trifurcation is "non-singleton gauge
orbit" in the apparatus. "Frame drift" is "temporal state mutation without classification
update." "Structural inconsistency" is "Boltzmann independence failure" or "beneficiary
structure inconsistency with claimed type." The mapping is real.

But it is not clean. The apparatus:
- Under-implements Type A relative to the trifurcation's emphasis
- Over-implements Type B (5+ instruments vs. the trifurcation's single category)
- Has a network-level failure mode (contamination propagation) with no trifurcation analog
- Detects a failure mode (cover stories) that requires two-level analysis the trifurcation
  doesn't anticipate
- Has cross-cutting subsystems where the same code serves multiple trifurcation types

The asymmetry has an explanation: the trifurcation was designed for philosophical
reasoning episodes (single analyst, short timeframe, one entity). The apparatus was
designed for structural analysis of social constraints (corpus-scale, long timeframe,
network of entities). The domain difference changes which failure modes are empirically
common and which require elaboration:
- Type A failures in static corpora require temporal evidence in measurement histories.
  Most testsets don't have it. One instrument is enough for what the data provides.
- Type B failures in a power-stratified classification system can manifest at metric,
  structural, network, and origin layers independently. Multiple instruments are needed.
- Type C failures (indexical) are foundational — the entire framework is built on them —
  and two instruments (orbit + cohomology) provide both detection and quantification.

**What this finding implies about the framework's lineage:**

The apparatus and the trifurcation were not designed together, and the trifurcation
was not used as a specification. But they share conceptual scaffolding at a level that
is not accidental — both are concerned with diagnosing reasoning failures in a
framework that takes perspective-dependence seriously. The partial mapping is evidence
that the two frameworks are "two products of the same intuition" (in the original
framing of the three possible answers). The intuition: classification failures are
structural, not random, and can be systematically categorized by their generative
mechanism.

The apparatus extends the trifurcation into territory the trifurcation doesn't name
(network-level failures, cover story concealment, multi-constraint coordination
patterns). This is not inconsistency — it's the domain-specific elaboration that a
general taxonomy requires to become a working diagnostic instrument.

## What Kind of Paper This Implies

A "trifurcation-to-apparatus mapping" paper would need to be honest about the
asymmetry. The most defensible claim is:

> The DR apparatus retrospectively operationalizes the trifurcation taxonomy.
> Each of the three failure types is represented by at least one clean instrument.
> The coverage is unequal: Type B (structural inconsistency) required multiple detection
> layers because the domain has a cover-story mechanism that systematically conceals
> structural inconsistency at the type surface while it remains visible at the chi layer.
> Type A (frame drift) required one instrument applied to temporal measurement data where
> available. Type C (indexical underspecification) required exactly two instruments that
> provide qualitative and quantitative detection of position-dependence.

The paper's contribution would be:
1. Showing that the trifurcation's abstract failure modes have concrete operational
   implementations in a working classification system.
2. Demonstrating that Type B is not one thing — it has a multi-layer structure
   (metric, structural, network, origin) that requires redundant detection.
3. Showing that a cover-story mechanism (the apparatus's most distinctive finding)
   is a Type B failure that produces apparent Type C resolution — surface consensus
   that looks like a global section but isn't.
4. Identifying the gap: Type A is thin in the apparatus, which tells you something
   about the limits of static corpus analysis for detecting reasoning-process failures.

**A paper claiming clean mapping would be overclaiming.** The asymmetry in coverage
(Type B rich, Type A thin) would be contradicted by anyone who reads drift_events.pl
alongside the five Type B subsystems. The paper would need to explain the asymmetry,
and the explanation undermines the clean-mapping claim.

**A paper on partial mapping is honest and informative.** The partial mapping is more
interesting than clean mapping would be: it tells you what the domain demands.

## Flags Section

Items outside the audit's scope that seem worth attention:

**1. The two-level measurement gap in the trifurcation vocabulary.**
The cover-story mechanism — where chi-level inconsistency is concealed at the
type-surface level — is the apparatus's most empirically significant finding (62.1
percentage-point chi-vs-type gap in tangled_rope, v5 §2.2). The trifurcation has no
vocabulary for this. If a "trifurcation-to-apparatus" paper is written, this is the
place where the apparatus most clearly extends the trifurcation rather than implementing
it. Calling attention to this gap would strengthen the paper's claim to originality.

**2. Cognitive Displacement as partial Type C.**
The δ-band analysis (`python/cognitive_displacement_sweep.py`) probes how robust the
indexical structure is to intra-position calibration variation. This is a Type C concern
(is the position specification precise enough to constrain classification?), but it's
applied at a sub-position level the trifurcation doesn't contemplate. The trifurcation
assumes that once you've specified an observer, you get a determinate answer. The
apparatus shows that two observers at the "same" structural position with different
cognitive orientations (δ) can disagree on classification. This is a finer-grained
Type C failure the trifurcation's vocabulary doesn't express.

**3. The Nash distance as Type B at the game-theoretic layer.**
Nash distance measures minimum reclassifications to achieve H¹=0 — the structural
distance to consensus. A Nash distance of 1 means one position's reclassification would
resolve all disagreement; a Nash distance of 3 means the disagreement is structurally
locked (distributionally forced by all four positions). This maps to Type B: whether
the disagreement is structurally forced (Type B — no one can escape it unilaterally)
or contingent (not Type B — someone could resolve it by changing their assessment).
The partition into positional extraction (Nash=1, 255 cases) and distributed extraction
(Nash=3, 153 cases) from v6.11 §5.5 is a within-Type-B structural distinction the
trifurcation doesn't anticipate. Worth noting in a paper on the relationship.

**4. The FNL pattern may be Type A in disguise.**
FNL (False Natural Law) detects constraints declared as `emerges_naturally` that fail
Boltzmann independence. The source of these declarations: the testset author asserted
`emerges_naturally` for a constraint that doesn't actually satisfy the Boltzmann
conditions. This could be a frame-drift failure (the analyst's frame at the time of
testset authorship treated the constraint as a natural law; the Boltzmann test reveals
the frame was wrong). Alternatively, it could be pure Type B (the assertion was simply
incorrect). The apparatus treats it as Type B; the trifurcation would need the
provenance of the assertion to distinguish. This is not a problem with the audit — it's
a genuine ambiguity at the boundary between A and B that the two frameworks handle
differently.
