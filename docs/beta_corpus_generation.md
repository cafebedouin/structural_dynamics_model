# Beta Corpus Generation Pipeline

## Purpose

Generate a clean, single-provenance beta corpus (v4) from the v3 constraint topics
using `gemini-2.5-pro` with search grounding. This tests **process independence**:
do the framework's invariants hold when the mixed-provenance iterative v3 build
is replaced by a uniform automated pipeline?

## What Changed from v3 Generation

| Aspect | v3 (mixed) | v4 (beta) |
|--------|-----------|-----------|
| **Provenance** | Mixed: gemini-2.0-flash, gemini-3.0, Claude, manual | Single: gemini-2.5-pro |
| **Process** | Iterative build-and-test, some manual | Automated batch |
| **Search** | No research grounding | Per-topic search via gemini-2.0-flash |
| **Prompt bias** | Corpus Balance Guidance section active | Stripped — model classifies from structure alone |
| **Type hint** | Some seeds had type guidance | NO claimed_type in seeds |

## Key Design Decision: No Type Hints

The seed extractor deliberately excludes `claimed_type` from seeds. The generating
model receives only: `human_readable`, `topic_domain`, and a brief summary. It
must determine the constraint type from structural analysis of the topic alone.

This means the v4 type distribution is an independent measurement. If the 80.1%
genuinely perspectival finding reproduces, it wasn't an artifact of the iterative
build process or type-hint contamination.

## Key Design Decision: No Corpus Balance Guidance

The generation prompt's "Corpus Balance Guidance" section (which steered toward
underrepresented types like tangled_rope and scaffold) is stripped programmatically.
This eliminates a known bias source in the v3 corpus. If the type distribution
shifts, that's signal about v3's bias.

## Key Design Decision: Type-Diverse Exemplar Seeding

The first 36-seed test run revealed severe metric homogeneity: 61% of constraints
produced an identical computed fingerprint (powerless=snare, moderate=snare,
institutional=rope, analytical=snare), 31/36 had extraction=extreme and
suppression=extreme, and 33/36 were strongly_coupled. The model was stamping
one structural template regardless of topic.

This is the same distributional context deficit identified in the presheaf
diagnostic (§3.5): without type-diverse examples, the model defaults to one
structural template. The presheaf experiment showed 3 cross-domain exemplars
raised the moderate atom rate from 40% to 88% (Fisher's exact, p < 0.0001).

The generator now includes a **single diagnostic exemplar** — `verification_bottleneck.json` —
that exhibits all six DR types from different perspectives on the same constraint.
This is more token-efficient than six separate exemplars (~800 tokens vs ~1800)
and teaches the core DR insight: type is perspectival, emerging from the observer's
structural position relative to fixed base properties. A metric diversity preamble
reinforces that metrics must match the topic's actual structure.

The exemplar demonstrates:
- **Mountain**: civilizational observer naturalizes the constraint (false summit)
- **Rope**: institutional beneficiary with arbitrage exit
- **Scaffold**: organized open-science coalition sees arXiv/registered reports as sunset
- **Piton**: journal editorial system sees degraded performative review (theater ≥ 0.70)
- **Tangled rope**: moderate replication group with mixed coordination/extraction
- **Snare**: powerless field reliability trapped with no exit

This preserves the process independence test: the model still receives no
`claimed_type` hint per seed. It just now has distributional context for what
all six types look like structurally.

## Pipeline Steps

### Step 0: Place Diagnostic Exemplar

```bash
# Copy the v1.1 verification_bottleneck.json to json/
cp verification_bottleneck.json json/verification_bottleneck.json
```

The generator looks for `json/verification_bottleneck.json` first, then
falls back to the v3 archive. This file exhibits all 6 DR types from
different perspectives and is included in the cached static context.

### Step 1: Extract Seeds

```bash
python3 python/seed_extractor.py
```

Reads `prolog/archives/prolog_v3/testsets/*.pl` and writes `prolog/beta_seeds.json`.
Each seed contains:
- `constraint_id` — from filename, **normalized** for schema compliance
- `human_readable` — from `human_readable/2` Prolog fact
- `topic_domain` — from `topic_domain/2` Prolog fact
- `summary` — first sentence of doc comment (if present, may be null)
- `original_id` — only present when normalization changed the ID

**ID normalization**: The JSON schema requires `^[a-z][a-z0-9_]*$`. The seed
extractor lowercases all IDs and prefixes digit-leading IDs with `n` (e.g.,
`8k_tv_limit_2026` → `n8k_tv_limit_2026`, `CG_IsraelGaza_20231012` →
`cg_israelgaza_20231012`). The `original_id` field preserves the v3 name
for cross-corpus mapping.

**You must re-run the seed extractor** after applying this update to get
normalized IDs. Delete `prolog/beta_processed.txt` and `json/*.json` /
`prolog/testsets/*.pl` to start the batch fresh.

### Step 2: Generate Beta Corpus

```bash
# Full run with search grounding (recommended)
python3 agent/generate_beta_corpus.py

# Test with 5 seeds first
python3 agent/generate_beta_corpus.py --limit 5

# Skip search grounding (faster, cheaper)
python3 agent/generate_beta_corpus.py --skip-search

# Disable context caching (fallback if caching API unavailable)
python3 agent/generate_beta_corpus.py --no-cache

# Resume after interruption (reads beta_processed.txt)
python3 agent/generate_beta_corpus.py

# Start from seed index 500
python3 agent/generate_beta_corpus.py --start-at 500

# Dry run — show what would be generated
python3 agent/generate_beta_corpus.py --dry-run
```

**Resumability**: The generator writes each completed constraint_id to
`prolog/beta_processed.txt`. On restart, it skips already-processed seeds.
To retry a failed seed, remove its line from the log. Ctrl+C is safe —
the context cache is cleaned up in a `finally` block, and progress is
preserved via the log file.

**Rate limiting**: 5-10s between calls with search, 2-5s without. The
generator uses exponential backoff for 429/503 errors.

### Step 3: Run Prolog Pipeline

After generation completes:

```bash
# From repo root
make -j4 quick
```

This runs the full analysis pipeline on the new testsets, generating
`outputs/corpus_data.json`, `outputs/enriched_pipeline.json`, etc.

### Step 4: Compare v3 vs v4

Key comparisons:
1. **Type distribution** — does the tangled_rope/snare/mountain ratio change?
2. **Genuinely perspectival rate** — does 80.1% reproduce?
3. **Sensitivity sweep** — are all 150 params still Inert at ±25%?
4. **Chi variance decomposition** — is f(d) still 94.9% of variance?

## Token Budget Estimate

**With context caching (default):**

The generation prompt + schema + example (~15k tokens) is uploaded once to a
Gemini context cache with 6-hour TTL. Each subsequent request sends only the
per-seed content (~200 tokens) + research context (~2k tokens). Cached input
tokens are billed at 75% discount.

- Cache creation: ~15k tokens (one-time)
- Per story: ~2k in (dynamic only) + ~5k out = ~7k tokens
- Research (flash): ~3k tokens per seed
- Total: ~15k + (1,151 × 10k) ≈ 11.5M tokens

**Without caching (`--no-cache`):**

- Per story: ~17k in + ~5k out = ~22k tokens
- Research (flash): ~3k per seed
- Total: 1,151 × 25k ≈ 29M tokens

Context caching cuts billed input tokens by ~60% for the generation calls.

**Cost at gemini-2.5-pro pricing:** Well within $200 either way, but caching
is free insurance and is on by default. Use `--no-cache` only if the caching
API is unavailable in your region or SDK version.

## Troubleshooting

**"No .pl files found"**: Ensure v3 testsets are archived at
`prolog/archives/prolog_v3/testsets/`.

**"No example JSON found"**: Copy `antifragility.json` to either `json/` or
the archive at `prolog/archives/prolog_v3/json/`.

**Validation failures**: The generator retries once with error feedback.
Persistent failures are logged and skipped. If you see
`does not match '^[a-z][a-z0-9_]*$'`, re-run the seed extractor to
normalize IDs.

**API rate limits**: The generator uses exponential backoff (up to 5 retries)
plus a 3-6s pause between research and generation calls. Inter-seed delay
is 8-15s with search, 3-8s without.

**Prolog syntax errors** (End of file in quoted atom / Operator expected):
The JSON→PL compiler now escapes single quotes in Prolog atoms (`'` → `''`)
and backslashes. The first 36-seed run had 45 syntax errors from unescaped
apostrophes in omega_variable fields. The fix is in `generate_constraint_pl.py`
(`_pl_escape()` and `_pl_escape_double()`).

**Patched constraint_id**: The seed now includes `CONSTRAINT_ID` explicitly
in the prompt. If the model still invents a different ID, it gets patched
back. Should be rare with the explicit instruction.
