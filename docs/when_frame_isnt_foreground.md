# When Frame Isn't Foreground

### Type A and the Limits of Module-Level Audit

#### Abstract

The trifurcation classifies three failure modes in analytical reasoning — Type A (frame drift), Type B (structural inconsistency), Type C (indexical underspecification) — and presents them in parallel as three components of equal status. This paper argues that the parallel presentation is misleading. In the Deferential Realism apparatus, Type A is not one of three failure components; it is the medium in which the apparatus operates, the frame-comparison architecture that Type B and Type C are subsidiary to, and the only failure type with no characteristic granularity at which it lives. The trifurcation's symmetric framing is a useful first approximation that obscures a structural asymmetry of position.

The paper develops three claims. First, the apparatus's primary work is inter-reasoner drift detection: every engine report compares an LLM-authored constraint hypothesis against the axiom-encoded frame of the apparatus and surfaces the gap. Type B detection and Type C indexing are subsidiary operations within this larger frame-comparison architecture. Second, Type A is granularity-promiscuous: a predicate-level investigation finds 46 Type A predicates across 10 files, of which two-thirds reside in modules a prior module-level audit either did not classify, did not mention, or classified as something other than Type A. Type B and Type C have characteristic granularities at which they cleanly localize; Type A does not. Third, the audit cataloging Type A coverage exhibited the failure mode it was cataloging — its frame on "what counts as a Type A module" drifted from the trifurcation's actual definition (frame mismatch between reasoning stages) to a narrower operational version (modules whose primary function is temporal-pattern detection). The recursion is not coincidental. It is what the central claim predicts.

This paper is the Type A counterpart to *When Splitting Isn't Solving* and *When Consensus Isn't Coherence*, but it is structurally different from both. Those papers extend a cell of the trifurcation by showing the apparatus refines what specification or detection can accomplish. This paper does not extend Type A in the same way. It argues that Type A is not a cell to extend — it is the lattice the cells sit in, and the appearance of parallel structure with B and C is itself a frame artifact.

#### 1. From Parallel Taxonomy to Layered Architecture

The trifurcation's original presentation lists three failure types in parallel, each with its own diagnostic tests, its own resolution prescription, and its own canonical paradoxes. Type A's prescription is frame-fixing: identify the unmarked state mutation, freeze the criteria, hold them constant across reasoning stages. Type B's prescription is detection: compute against the structural axioms and surface inconsistency where it occurs. Type C's prescription is specification: complete the indexing before evaluation, and the paradox often dissolves into several distinct questions with consistent answers each.

The presentation invites a symmetric reading. Three types, three tests, three prescriptions, three classes of paradox. The asymmetry paper develops the first refinement of this picture: the three types correspond to three different relations between failure and formalism — contradiction-to-structure, contradiction-to-specification, contradiction-to-governance — and the apparatus's coverage of the three is asymmetric not by accident but by what kinds of formalism each type admits.

This paper develops a second refinement. Within the apparatus, Type A is not parallel to B and C even at the architectural level, because the apparatus's primary work *is Type A*. Every engine run compares two frames: the LLM-authored constraint hypothesis (encoded as a `.pl` file with declared metrics, claimed type, structural properties, beneficiaries, signatures) and the apparatus's axiom frame (the structural rules under which any claim of type T must satisfy properties P, Q, R). The engine's output is the gap between these two frames, made legible. Every report — the false_summit_mountain alert, the FCR override, the perspectival incoherence flag, the hub conflict, the oracle gap — is an instance of inter-reasoner drift detection. The classical Type A puzzle was *intra-reasoner* drift, where one analyst's frame drifted across reasoning stages without being marked. The engine instruments *inter-reasoner* drift at scale: the LLM and the axioms are two reasoners whose disagreement is the engine's primary diagnostic output. Both are frame mismatch between reasoning stages. The intra version was Plutarch's puzzle. The inter version is what the apparatus does on every constraint it processes.

On this reading, Type B and Type C are subsidiary to the larger Type A architecture. Type C's prescription — required indexing — is what makes inter-reasoner frame comparison well-defined. You cannot compare two frames that aren't both fully specified; the schema-level requirement that all indexing fields be complete before validation can run is the precondition for the comparison the engine performs. Type B's detection is what surfaces when inter-reasoner frame comparison detects structural axiom violations. The structural-signature cascade, the Boltzmann compliance check, the FSM/FCR/FNL detectors — these all fire when the LLM's frame disagrees with the axiom frame on whether a constraint's claimed type is consistent with its structural properties. The disagreement is what gets surfaced; the surfacing mechanism is the apparatus's Type B machinery.

This is not a claim that Type B and Type C dissolve into Type A. They retain their own shapes — there are Type B failures (structural inconsistency under fixed frame) and Type C failures (indexical underspecification under fixed frame) that are not reducible to the inter-reasoner architecture. The claim is that the apparatus, as built, performs Type B and Type C detection *in service of* the larger Type A function of comparing frames, and that the trifurcation's symmetric three-component presentation obscures this asymmetry of role. Frame is not foreground in this picture. Frame is the picture.

#### 2. Type A as the Apparatus's Medium

The architectural claim has practical signatures throughout the apparatus. Each constraint enters the pipeline as an LLM-authored `.pl` file: a structured hypothesis declaring base extractiveness, suppression score, theater ratio, claimed type, beneficiary structure, structural properties, signatures, drift evidence. The hypothesis is the LLM's frame on the constraint, externalized in code. The apparatus's axioms are encoded in the rule cascade, the structural-signature definitions, the Boltzmann compliance tests, the gauge orbits, the cohomological obstruction calculations, the drift-event detectors. The axioms are the apparatus's frame on what any well-formed constraint of a given type must satisfy. The pipeline runs the first frame against the second, and the engine's output is the resulting comparison.

The empirical character of this comparison is visible in any individual report. A constraint declared as `mountain` may pass the metric thresholds (low extractiveness, low suppression, low theater) and yet have two identifiable beneficiaries asserted in the testset; the FSM detector fires, the false_summit_mountain signature is recorded, the report surfaces the inconsistency between the LLM's claim of type and the structural conditions for the claimed type. The apparatus is not merely detecting "Mountains have no beneficiaries" as a Type B inconsistency in the abstract. It is detecting that the LLM's frame and the axiom frame disagree about whether this specific constraint is a Mountain. The disagreement is the report.

The same architecture appears in less obvious places. Perspectival incoherence flags inter-reasoner disagreement on classification across observer positions. Oracle gap surfaces cases where a single-position MaxEnt is confident but cross-position cohomology shows obstruction — a frame-comparison between the local view (LLM-style confidence at one position) and the global view (the apparatus's full multi-position structure). Hub conflicts arise when two of the apparatus's own structural detection mechanisms produce conflicting signals on a single constraint, surfacing inter-component disagreement within the apparatus's own frame. Even the abductive engine, which the audit identified as a meta-diagnostic synthesizer, can be read in this register: it is comparing the apparatus's various subsystem outputs against each other and surfacing the patterns of agreement and disagreement, which is frame-comparison performed at the level of subsystems rather than constraints.

Type B and Type C remain real and important within this architecture. The apparatus has Type B detectors and Type C indexing because frame-comparison without them would not be well-defined or computationally tractable. But the function of the detectors and the indexing is to enable the comparison, not to be the apparatus's primary work. The primary work is the comparison itself. This is what I mean by Type A as the apparatus's medium. It is the substrate within which Type B and Type C operations make sense, and it is invisible to the audit precisely because it is everywhere.

#### 3. Granularity-Promiscuity

Type B and Type C each have a characteristic granularity at which they cleanly localize. Type B failures are about structural inconsistency between a constraint's claims and the axioms its claimed type entails — a per-constraint operation, naturally implemented at the module level. The Boltzmann compliance check is one module; the structural-signature cascade is one module; the purity score is one module. Type C failures are about indexical underspecification — a per-query operation, also naturally implemented at the module level. The gauge orbit machinery is one module; the cohomological obstruction is one module. Both have a granularity at which they cleanly sit, and that granularity matches the unit of analysis a code audit naturally uses. So a module-level audit finds them.

Type A failures are about frame mismatch between reasoning stages, and this is granularity-promiscuous by definition. Frame mismatch can happen between two stages of one analyst's reasoning (intra-reasoner drift). Between two reasoners (inter-reasoner drift, as in the LLM-versus-axioms architecture). Between a frame and its referent (mesofact drift, as when the world changes under a stable frame). Between a description and the thing described (drift between paper claims and code behavior). Within a single comparison operation (a temporal predicate fetching state at one time and comparing it to another). All of these are Type A failures under the trifurcation's actual definition. None of them has a single characteristic granularity at which it lives. So Type A material gets distributed across whatever granularity each instance of frame-comparison happens to operate at, and a single-granularity audit will only catch the instances that match its chosen granularity.

A predicate-level investigation of the Deferential Realism codebase confirms this empirically. The investigation collected 46 predicate candidates with Type A semantics — temporal or version indexing, frame-mutation tracking, comparison across stages, lifecycle or progression operations. Of the 46, 16 reside in the one module the prior module-level audit classified as Type A (`drift_events.pl`). The remaining 30 reside in nine modules the audit treated otherwise: three modules the audit did not mention at all (`coercion_projection.pl`, `pattern_analysis.pl`, `intent_engine.pl`); one module mentioned only obliquely as part of a facade group (`drl_composition.pl`, with ten Type A predicates implementing a complete classification-label transformation chain that the audit did not examine); one module classified as Outside the trifurcation (`network_dynamics.pl`); one module classified as cross-cutting A+B+C with the Type A content named at the dimension level but not at the predicate level (`logical_fingerprint.pl`); one module not primarily classified but doing temporal-gradient computation (`drl_counterfactual.pl`); and one module not classified at all but enforcing the structural preconditions for temporal data (`data_verification.pl`).

Two thirds of the apparatus's Type A predicate-level material lives outside the one module the audit identified as Type A. This is not a marginal correction. It is a structural finding about how Type A material distributes through the apparatus, and the distribution pattern matches what granularity-promiscuity predicts: Type A doesn't localize, so a module-level inventory misses everything that doesn't happen to be in a module whose name and primary function are already about drift.

The investigation surfaces a second finding that the module-level audit could not have surfaced. Type A in this apparatus exists in at least two architectural varieties. The first is *metric-level*: `drift_events.pl` and its helper predicates operate on continuous measurements (extraction delta, coordination loss, theater accumulation), comparing values across timestamps and firing detectors when changes cross thresholds. The second is *classification-label-level*: the transformation-tracking chain in `drl_composition.pl` (`constraint_history/3`, `dr_type_at/3`, `transformation_detected/5`, `transformation_type/6`, `canonical_transformation/6`, `predict_transformation/3`) operates on discrete type assignments, fetching what type a constraint was at time T and what type it is at time T', and characterizing the change semantically. These are two parallel Type A architectures performing the same general function (frame comparison across reasoning stages) at different levels of abstraction. The audit examined only the first. The second has 10 predicates, an entire chain that runs end-to-end on temporal data, and was missed entirely.

The discovery of two architectural varieties of Type A within a single apparatus is itself a methodological finding. It suggests that Type A in any apparatus may have multiple architectural forms that need to be distinguished, and that the trifurcation's single category "frame drift" is correct as a high-level description but may underdetermine the implementation-level structure. A taxonomy of Type A sub-varieties — metric-level, label-level, configuration-level, schema-level, possibly others — is a natural object for further work.

A third finding is more flag-worthy than fully grounded. Two predicates in the apparatus (`dr_type_at/4` in `drl_composition.pl` and `classify_snapshot/3` in `transition_paths.pl`) carry explicit DEPRECATED markers in their headers, noting that they use a legacy classification path (`power_modifier/2` multiplication) instead of the canonical sigmoid pipeline used by `drl_core:dr_type/3`. Both are still loaded at runtime and called from active code paths. If the deprecated path produces classifications that diverge from the canonical path, the apparatus has live frame drift between two versions of its own classifier, and downstream Type A analysis (transformation chains, degradation chains) carries forward whichever classification the deprecated path produced. Whether the divergence is empirical (the paths actually return different results on current data) or merely documentary (the markers are stale and the migration has been completed) is a question this paper does not resolve. The structural risk it points to is real regardless: any apparatus with deprecated paths still in execution has a Type A risk that does not appear in any module-level audit because deprecation is a code-organization property, not a module-classification property. Whether this particular apparatus has the live form or only the documentary form needs follow-up empirical work — but the existence of the risk is itself a Type A finding the module-level audit could not have surfaced.

#### 4. Recursive Instances

The architectural claim — that Type A is the apparatus's medium and is granularity-promiscuous — has a sharper signature than the predicate-level distribution: instances where the failure mode shows up in the very activities meant to catalog or describe it.

The clearest case is the audit itself. The trifurcation-to-apparatus mapping audit (May 2026) examined the codebase module-by-module and classified each subsystem against the three trifurcation types. Its primary Type A finding was that the apparatus has "one clean Type A subsystem" — `drift_events.pl` and the lifecycle facade that wraps it — and that Type A coverage is "thinly covered" relative to the trifurcation's emphasis. The audit defended this finding partly on data-availability grounds (most testsets carry point-in-time data, not longitudinal series) and partly on architectural grounds (the apparatus implements Type A in fewer places than B or C). The predicate-level investigation reported in the previous section refutes the architectural part of the defense. The audit found one Type A module because the audit was looking for Type A modules — its operational frame was "subsystem whose name or primary function is drift detection." Under that frame, `drift_events.pl` is what shows up, and that's because `drift_events.pl` is the only module whose name and primary function are drift detection. The frame caught what the frame was constructed to catch and missed everything else.

This is itself a Type A failure under the trifurcation's actual definition. The audit's frame on what counts as Type A material drifted from the trifurcation's general definition (frame mismatch between reasoning stages) to a narrower operational version (modules with drift in their name or primary purpose). The drift was unmarked. The audit operated as if "Type A modules" were exhaustive of Type A coverage. The result was a "Type A is thin" finding that reflects what the audit's frame *could see* of Type A, not what Type A actually is in the apparatus. The audit, designed to catalog Type A coverage, exhibited the failure mode it was cataloging — and the recursion was not coincidental. It is what the granularity-promiscuity claim predicts: any single-granularity inventory of Type A will miss the instances that don't match its chosen granularity, and the inventory's claim of comprehensive coverage is itself an unmarked frame.

The Ship of Theseus is a second instance, at a different scale and over different timescales. Plutarch's puzzle posed a question about identity persistence in a polity: when does the gradual replacement of components compromise the identity of the whole? The puzzle was originally about civic continuity — what makes Athens still Athens after a generation of citizens has died and been replaced. Through the medieval and early modern reception, the puzzle became a metaphysical teaching case about identity over time. By the late twentieth century it was a stock example in introductory philosophy texts. By 2026 it has become a kind of cliché — invoked in films and television as a token of philosophical depth, a way of gesturing toward a difficult question without engaging with one. The puzzle's cultural function has drifted from civic to metaphysical to pedagogical to ornamental. The same words now do different work than they used to.

This drift is itself a Type A failure under the trifurcation's definition: the frame within which the puzzle is interpreted has mutated across reasoning stages without being marked. A reader in 2026 who encounters the Ship in a film and a reader in Plutarch's Athens are not asking the same question, but the surface form of the question is identical, and the assumption of stability is automatic. The puzzle that was meant to teach about Type A failure has itself undergone Type A failure in its function — and the trifurcation paper's reframing of the puzzle as state-management rather than identity-metaphysics is, partly, an act of marking the drift. The puzzle is not what it was. Treating it as if it were — using it as a teaching case as if its function were stable — is the failure mode.

Mesofacts are the everyday class where this same pattern operates without philosophical weight. Samuel Arbesman's coinage names a category of facts that change on intermediate timescales — slow enough to feel stable, fast enough to drift within the window of normal reasoning. The population of New York. The current consensus on a contested scientific question. The list of countries with given political systems. The tallest building. What Pluto is. Each of these has the property that an analyst who learned the fact at age twenty and applies it at age forty will probably be operating with a stale frame, and the staleness will not register because the frame's stability is automatic. Mesofacts are Type A failures in waiting. The failure isn't that the analyst's reasoning drifts — the analyst is reasoning consistently and well within the frame they have. The failure is that the world has drifted under the frame, and the frame's stability has become the failure mode rather than its protection.

A fourth potential instance is the deprecation finding from the predicate-level investigation. If `dr_type_at/4` and `classify_snapshot/3` produce classifications that diverge from `dr_type/3` on current data, the apparatus is carrying live frame drift between its own classification stages — the same apparatus whose primary work is detecting frame drift. As noted in the previous section, this is currently flag-worthy rather than confirmed, and a follow-up empirical check is needed before it can be cited as a live instance. But its potential existence is structurally significant. The apparatus that catalogs frame drift may itself carry frame drift in its implementation, just as the audit that catalogs Type A coverage exhibited Type A failure in its method.

These instances are not coincidental. They are what the granularity-promiscuity claim predicts: Type A failures happen at whatever level frame-comparison happens at, and the activities of cataloging, describing, auditing, and inventorying are themselves frame-comparison operations subject to Type A failure. The Ship of Theseus's cultural drift, the audit's frame-fixing on "drift module," and the apparatus's potential internal frame divergence are three instances of the same point: Type A coverage cannot be assessed from within a single frame, because the frame chosen is itself prone to the failure being assessed.

#### 5. Implications for Analytical Apparatus Design

If Type A is granularity-promiscuous and the apparatus's medium rather than one of its components, several methodological consequences follow for the design of analytical apparatuses generally.

First, cataloguing Type A coverage requires multi-granular inventory. A module-level audit can give an accurate count of Type A modules, but it cannot give an accurate count of Type A material. Predicate-level (or function-level, or operation-level, depending on the implementation language) inventory is needed to surface the distributed instances. A claim about Type A coverage that is grounded in a single granularity should be qualified accordingly — it is a coverage claim *at that granularity*, not a coverage claim about the apparatus.

Second, Type A may have multiple architectural varieties within a single apparatus that need to be distinguished. The Deferential Realism codebase has at least two — metric-level and classification-label-level — and the audit's single-category Type A treatment did not distinguish them. Other apparatuses may have configuration-level Type A (frame drift in tunable parameters), schema-level Type A (frame drift in the data structures the apparatus operates on), or process-level Type A (frame drift in the order and dependencies of pipeline stages). A taxonomy of Type A sub-varieties — initially derived from one apparatus's structure but generalizable through comparison — is a useful object for future work.

Third, audits and self-descriptions of analytical apparatuses are themselves vulnerable to Type A failure and need their own external review. The audit reported on in this paper was internally consistent and methodologically careful at the granularity it operated. Its findings were correct as far as they went. The failure mode was that "as far as it went" was not far enough, and the limit was invisible from within the audit's frame. This is the strongest case for external review as a complement to internal audit: internal audit fixes the frame in which the apparatus is examined, and frame-fixing is the right move for finding Type B and Type C inconsistencies under a stable frame, but it does not address whether the frame itself is the right one to fix. External review, with a different frame, can see what internal review's frame excluded. The asymmetry paper's case for governance as the appropriate response to Type A finds its concrete instantiation here: the apparatus's audits and self-descriptions need governance structures that include external review by reasoners with different frames.

Fourth, the trifurcation's symmetric presentation of A/B/C is a useful first approximation but obscures a structural asymmetry of position. Type B is one of the apparatus's diagnostic operations. Type C is the precondition under which the diagnostic operations are well-defined. Type A is the medium within which those operations sit and the architecture under which inter-reasoner comparison happens. The three are not three components of equal status; they are three different layers of a single architecture. Restating the trifurcation's diagnostic prescriptions with this asymmetry in mind — Type C makes comparison well-defined, Type A is the comparison itself, Type B is what comparison surfaces when axioms are violated — gives a clearer picture of what the apparatus is doing and where its failures live.

#### 6. Conclusion

The trifurcation paper's three failure types — A, B, C — were a useful taxonomy. They are not three components of equal status in the apparatus that has grown out of the framework. Type A is differently positioned from B and C: it is the apparatus's medium, its primary architectural function (inter-reasoner frame comparison between LLM-authored hypothesis frames and axiom-encoded apparatus frames), and the only failure type with no characteristic granularity at which it lives. Type B and Type C have characteristic granularities and cleanly localize at the module level; Type A is granularity-promiscuous and distributes across whatever level frame-comparison happens at.

A predicate-level investigation finds 46 Type A predicates across 10 files in the Deferential Realism codebase, with 30 of them in nine modules a prior module-level audit either did not classify, did not mention, or classified as something other than Type A. The audit's "Type A is thin" finding reflected what the audit's frame could see of Type A, not what Type A actually is in the apparatus. The audit, designed to catalog Type A coverage, exhibited the failure mode it was cataloging — its frame on what counts as Type A drifted from the trifurcation's actual definition (frame mismatch between reasoning stages) to a narrower operational version (modules with drift in their name or primary purpose). The recursion was not coincidental. It is what granularity-promiscuity predicts.

Three other instances of the same recursive pattern: the Ship of Theseus's cultural drift over 2,500 years, in which the canonical Type A puzzle has itself undergone Type A failure in its function; mesofacts as the everyday class where stable frames meet a drifting world; and the potential frame divergence between deprecated and canonical classification paths in the apparatus's own code, which would mean the apparatus tasked with detecting frame drift carries unmarked frame drift in its implementation. The three instances differ in scale, in confidence, and in domain, but they instantiate the same architectural point: Type A failures happen at whatever level frame-comparison happens at, and the activities of cataloging, describing, and auditing are themselves frame-comparison operations subject to the same failure mode.

This paper is the Type A counterpart to *When Splitting Isn't Solving* and *When Consensus Isn't Coherence*, but it makes a different kind of move than those papers do. They extend a cell of the trifurcation by showing the apparatus refines what specification or detection can accomplish. This paper does not extend Type A in the same way. It argues that the trifurcation's symmetric three-component presentation obscures Type A's differently-positioned role, and that the apparatus's central function is best understood as inter-reasoner frame comparison with Type B and Type C as subsidiary operations within that larger architecture. Frame is not foreground in this picture. Frame is the picture, and the trifurcation's parallel framing of A, B, and C is itself a useful frame whose limits this paper makes visible.

The eventual synthesis paper that draws the project's findings together will need to integrate this asymmetry into the trifurcation's presentation directly — perhaps by foregrounding the architectural layering (Type C as precondition, Type A as comparison, Type B as detection) rather than by listing three failure modes in parallel. The current papers each surface a piece of this larger picture, and the discipline of writing them as they present themselves rather than forcing premature synthesis is consistent with what the framework's apparatus instantiates. Frame-comparison happens locally, at whatever level the comparison happens at; the larger pattern emerges only when the local comparisons accumulate enough to make their shared structure visible. This is true of the apparatus's analysis of its corpus, of the project's analysis of the apparatus, and of any analytical activity that takes its own frame seriously enough to keep it open to revision.
