# module_boundary_allowlist.txt — sanctioned cross-module qualification bypasses (OQ-68).
#
# One row per (module, predicate) that is referenced as `module:pred(...)` from OUTSIDE the
# module while NOT appearing in that module's export list (transitively, through any
# `:- reexport`). The guard is python/module_boundary_check.py, gate row `module bounds`.
#
# GRAMMAR (checked; a malformed row is RED, never a skipped line):
#     <module>:<pred>/<arity>   ROLE=<role>   <reason>
# The reason column is REQUIRED. A bare path list decays into "sites someone silenced" —
# the same convention axis_boundary_allowlist.txt carries.
#
# THE RULING THIS FILE ENCODES (operator, 2026-08-18). The deciding axis is WHO OWNS THE
# WRITE, not exported-vs-qualified:
#   * module asserts, outsiders only read  -> encapsulation is real -> ACCESSOR.
#   * outsiders assert into a namespace the module merely HOSTS -> nothing to breach ->
#     QUALIFICATION IS THE IDIOM: declare it here, do not export it.
# Exporting the corpus-schema predicates was ruled AGAINST: writers would still have to
# qualify their heads or declare `multifile` locally, so it changes name resolution across
# 100+ modules and still leaves qualified writes. All cost, no consolidation.
#
# FOURTH DISPOSITION — an EXTENSION of the ruling, recorded 2026-08-18. An outsider writes,
# BUT the namespace owner reads and enforces an INVARIANT over what was written -> WRITE
# ACCESSOR, fail-loud. The hosting test is not "who asserts" alone; it is whether the module
# merely holds the facts or also means something by them. Instance:
# diagnostic_summary:maxent_attempted/1 — json_report does the retractall/assertz, but
# diagnostic_summary interprets the marker, so an unrecognised stage would sit unread and the
# void gate would report a clean run over it. There is therefore no allowlist row for it. A
# pure host takes a row; a host with an invariant takes a write accessor.
#
# ROLE=internal-state IS NOT A LEGAL VALUE. A store whose module owns the write gets an
# accessor, not a row. If you are reaching for it, you want the accessor.
#
# IF THE GUARD FIRED AND ROUTED YOU HERE, read this before adding a row:
#   ARM A (undeclared bypass) — first ask which side of the ruling you are on. If the
#     module asserts and you only read, add an EXPORTED accessor there and swap your call;
#     do not add a row. A row is right only when the write comes from outside.
#   ARM B (corpus-schema without a production-side :- multifile) — add the predicate to the
#     multifile block in prolog/narrative_ontology.pl IN THE SAME CHANGE. A declaration
#     under tests/ does not count: the production load chain never consults those files.
#   ARM D (an unwired schema predicate acquired a consumer) — you are the FIRST consumer of a
#     predicate that is declared for load-correctness only. On a leg with no writers it is
#     defined-but-EMPTY, so a failed read means "no data authored here", not "the relation
#     does not hold". Decide which your consumer needs, handle absence explicitly, then remove
#     the UNWIRED_SCHEMA entry in the same change.
#   ARM C (a testset writes a head with no row) — either it is a genuinely new schema
#     predicate (row + production-side multifile, same change) or IT IS A TYPO. Arm C is
#     the typo detector that `:- multifile` silences: once a predicate is multifile, SWI
#     stops warning on redefinition, and that warning was doing the job by accident.
#
# WHY THIS IS NOT OPTIONAL BOOKKEEPING. narrative_ontology.pl carries its own tombstone for
# story_provenance/8 + story_seed/3: declared dynamic-only, they loaded 1/N ("Redefined
# static procedure" per testset consult, last-file-wins), fixed 2026-06-13. Two more members
# had silently fallen out of the set by 2026-08-18 — flat_control_of/2 declared NOWHERE
# engine-side, has_sunset_clause/1 `:- dynamic` but never `:- multifile`. Both were correct
# on disk only because every writing testset happens to emit a local declaration. Stripping
# that local declaration from all 28 loaded flat_control_of writers on a scratch leg:
#     without the central :- multifile -> 1 of 28 rows loaded, 27 warnings
#     with it                          -> 28 of 28, no warnings
#
# Rows are grouped by role and sorted. Generated by the introducing sweep, then hand-annotated;
# regenerate ONLY with review — a reason is a judgement, not a derived string.
